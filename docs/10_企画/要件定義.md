## 0. 決め方
- **Must** = M4 の製造 3.5h【仮定】で作る。再訪の因果（すごろく・再訪判定・予言・次回クーポン）と競技制約（地図・出典・オフライン・外部通信なし・入力検証）を優先した。
- **Should** = M4 で時間が余れば作る。余らなければ M5 で「未実装・理由」を本書に残す（`AI-DLC軽量版.md` §4）。
- **Could** = 今回は作らない候補。
- **受け入れ基準（AC-xxx）は通し番号**。試験項目 `T-xxx` は同じ番号の AC を1つだけ確かめる（T-017 ⇔ AC-017。`docs/40_試験/試験項目.md`）。
- 試験の方法: **U** = Vitest（サーバーは実 Express を一時ポートで起動して fetch、DB は `:memory:`）、**E** = Playwright（1並列・本番ビルドを Express が配信・DB は `:memory:`）、**M** = 手動。
- 「今日」は**アプリ内の今日**（JST）。DEMO_MODE のときだけデモで進められる（R-044）。

## 4. Should・Could の扱い
- Should（R-029・R-034・R-039・R-047・R-048）は U-01〜U-08 の後に時間があれば作る。作ったら AC と T を足す。作らなければ M5 で「未実装・理由」を書く。
- Could（R-060〜R-062）は今回作らない。理由: R-060 はふりがな辞書の保守が重い（index.html では辞書の最長一致）、R-061 は React と Leaflet の DOM 操作の確認が要る、R-062 は 127.0.0.1 の listen で十分【仮定】。

## 4.1 作らないもの（2026-11-09 15:33 追記。M3 ゲートのチェックリスト確認で、要件に書くべき「作らない」ことを足した）
- **ライブの音声・映像**は作らない（WCAG 1.2.4 は対象外）。音は効果音と読み上げだけ（どちらも止められる、R-037）。
- **時間制限**は作らない（WCAG 2.2.1）。読み上げ・トースト・さいころの演出は利用者の操作を待たせたり打ち切ったりしない。クーポンの期限（§5 の3、60日）は操作の時間制限ではなく特典の条件として画面に日付で出す。
- **認証・本人確認**は作らない（WCAG 3.3.8。R-001 ログインなし・ダミー ID）。パスワード・パズル・文字の書き写しを求めない。
- **利用者が HTML を書く機能**は作らない（SEC-XSS-11）。自由入力はひとこと（R-014、文字だけ・100字まで）の1つで、文字のまま描画する。
- 言語の範囲は**やさしい日本語と英語**（R-035）。外国語の固有名詞に `lang` を付ける（INC-06）。

## 5. 【仮定】（本書で決めたこと）
1. 旅の2日目のボーナスは +1、再訪は +2（「旅の2日目は再訪より小さい」方向性 §7。数は index.html の「さいころが1回振れるよ」に合わせた）。
2. 「1スポット1日1回」はきっかけごと（QR・ひとこと・誘う）。予言の答え合わせの +2 は別に数える。
3. 次に来た日から使えるクーポンは「手に入れた日の7日後から」、期限は手に入れた日から60日【仮定】。
4. 文字の大きさは index.html の小・中・大（15・17・20px）。方向性 §4 の「標準・大・特大」を置き換える。
5. 位置のデモは「いる場所」をスポットから選ぶだけ。ふだんは位置を使わない（Permissions-Policy で geolocation を無効）。
6. うわさの「昨日」「過去1か月」は、CSV の最後の日をアプリ内の「昨日」に合わせて数える（CSV の期間 10-01〜10-20 を今日の前に並べ直す）。
7. 「一緒に来た人」は CSV に無いので、ダミー利用者の ID から決まった計算で付ける（データ設計）。
8. 「すごろくを遊ばない」（R-039）とふりがな（R-060）は index.html にあるが Should／Could にした。
