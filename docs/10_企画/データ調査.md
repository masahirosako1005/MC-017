## 3. 方向性への反映（事実に合わせて直すもの）

1. 年齢のプルダウンは CSV に合わせて **10代・20代・30代・40代・50代・60代以上** の6区分にする（方向性.md §4 の【仮定】「10歳未満〜70代以上」を置き換え）。
2. 「一緒に来た人」は CSV に無いので、ダミー利用者に付ける（付け方は M3 のデータ設計）。
3. CSV の取込では、**履歴（12・18）を正**とし、13 の集計列（スタンプ獲得数・特典獲得数）は使わずに検証だけする。食い違い（227人）は取込時の検証結果として記録する【仮定】。
4. 人気の差・時間帯の偏りは CSV では小さい／不自然なので、うわさは**ダミーの行動データ**（名古屋のスポットの営業時間内に作る）を主に使う【仮定】。
5. 既存アプリに「周回（2周目）」があるため、**2枚目のすごろくは同じ盤の繰り返しにしない**（特典マスが増えるだけでなく、盤やマスの中身を変える）。焼き直しの指摘を避ける。

## 4. 追加したほうがよい機能の候補

データから見えた候補。**2026-11-09 11:47 にユーザーが C1〜C8 をすべて採用**し、`方向性.md` §13 に入れた。「再訪の因果」は 体験 → 気持ち → 次に来る理由。

| # | 候補 | 根拠（本書 §2） | 再訪の因果 | 推し度【仮定】 |
|---|------|-----------------|------------|----------------|
| C1 | **旅の2日目と再訪を分ける**: 前回から一定の日数（例: 7日）あいた時だけ「再訪ボーナス」を出し、連続した日は「旅の2日目」として別の小さなボーナスにする | 2日以上の利用はほぼ連続した日、3日以上あいた戻りは0人 | 1泊2日の旅の中でボーナスを使い切らない → 「次の旅で取っておいた続き」が残る | 高 |
| C2 | **移動の安心情報**: おすすめコースに所要時間・歩く距離・段差の少なさ・休憩所の数を出し、「ゆっくり・段差少なめ」コースを選べる | 要望の約3割（95件）が移動の不安。60代以上が最も熱心 | 不安なく回れた → 次は別のコースも行けそう → 次のコースを予約する気持ちで帰る | 高 |
| C3 | **スポット詳細に「近くのお店」**: レジ横 QR のあるお土産屋・飲食店を、そのスポットから近い順に出す | 要望「周辺店舗の情報も欲しい」20件 | 寄り道でさいころが増えた → お店を覚える → 次回も同じ店や別の店へ寄る（買い物の増加） | 高 |
| C4 | **使い方を迷わせない**: 特典の「使い方・使えるお店・期限」をクーポンに明記し、初回だけアバターが QR・ひとこと・誘うの手順を1つずつ案内する | 特典の受け取り方で迷った16件、操作の分かりにくさ10件 | 迷わず特典を使えた → 次も使える | 中 |
| C5 | **次回から使える特典**: 特典マスの一部を「次に来た日から使えるクーポン」にする（季節で中身が変わる） | 特典①→③で約4割に減る、景品の種類・魅力への不満19件 | 今は使えないクーポンが手元にある → 使いに来る | 中 |
| C6 | **みんなのひとこと（ダミー）**: スポット詳細とうわさで、ほかの旅行者のひとこと（ダミーのみ）を年代・一緒に来た人つきで読める。自分のひとことはほかの人に見せない | 良かった点の最多が「旅先の交流」69件 | 同じような旅行者の感想を読む → 行ってみたい場所が増える | 中 |
| C7 | **リマインドは自分で選ぶ・回数を選ぶ**: 季節イベントのリマインド（モック）は、自分で選んだイベントだけ、頻度も選べる | LINE 連携 215人のうち友だちブロック 20人（約9%） | うるさくない → ブロックされずに次の季節に届く | 中 |
| C8 | **2枚目は盤を変える**: 2枚目は別のエリアや季節のマスを入れ、1枚目と同じ道をなぞらない | 既存アプリに2周目が既にあり、121人が利用 | 新しい場所が出てくる → 2枚目を進めに来る。既存の周回との違いを明確にする | 中（§3-5 と同じ） |

- 推し度は、再訪の因果の強さ・データの根拠の量・Must を増やす負担で付けた【仮定】。
- 混雑（5件）は、うわさの「空いている時間帯」で既に扱う。スポットの説明（10件）は、架空のスポットだけ説明を厚くする（実在施設は名称と位置だけ、方向性.md §3）。
