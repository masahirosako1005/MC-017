# SC-A02 ダッシュボード（画面設計）

作成: 2026-11-09 15:33（実測） / 位置づけ: 追加企画（運営画面）。要件定義へは未反映 / モック: `docs/10_企画/画面モック/SC-A02_ダッシュボード.html`（1対1。見た目の正は `admin.html#a02`）
上流: 運営向け画面_仕様案 §1（目的）、§4（指標 K-01〜K-03・K-07、小さい数を隠す）、§5（SC-A02、Must）、§5.1、§6.1（気づき I-01〜I-06）、§8（`/api/admin/summary`）。

## 1. 目的
観光協会の担当が最初に見る画面。**「どうしたら再訪につながるか」**に対して、満足度ではなく「次に来る理由を持って帰ったか（K-03）」と「本当にまた来たか（K-02）」を、前の期間との差つきで見せる（既存のスタンプラリーとの比較は出さない）。気づき（上位3件）で、**どこに困りごと・減りがあるか**と、次に見る画面（SC-A03・SC-A04）を示す。

- 気づきの並び: I-01〜I-06 の番号順に条件を満たすものから3件【仮定】（同じデータなら同じ並び）。
- 小さい数: カードの人数が5人未満なら数字の代わりに「5人未満」。率の分母が30人未満なら数字の横に「参考」（灰色の枠と文字）を付ける（仕様案 §4）。
- 応答と画面に利用者の ID（`guest-xxxxxx`・CSV の ID）を出さない。

- 使いにくくなる人と対策（INC-01）: 統計に慣れていない担当→カードごとに「定義」で何を数えたかが分かり、関係と原因を取り違えないよう気づきに注記を付ける。
- だれのための工夫か（INC-03）: 色だけに頼らない差の記号は色覚に特徴がある人のためだが、白黒で印刷して会議で配る人にも効く。

## 9. 試験で確かめる観点（仕様案 §9 から。合否は書かない）
- 指標の計算: 決まった小さいデータで K-02・K-03 の値が手計算と一致する（旅の2日目 `day2` を再訪に数えない、境界の7日ちょうどは再訪になる）。
- 気づき: 同じデータなら同じ3件が同じ順で出る。I-01 は5ポイントちょうどで出る。I-02 は片方が29人なら出ない。
- 個人情報: 応答に `guest-` と CSV の7桁 ID が含まれない。5人未満のカードが数字で出ない。
- 入力: 期間の逆転・367日以上・配列の query（`?from=a&from=b`）・未知のキーが 400。
- 権限: 店舗の役割で `/api/admin/summary` が 404。`ADMIN_MODE` なしで 404。
- アクセシビリティ: 差が記号と文字で分かる、キーボードだけで期間を替えられる、200% 拡大で横に流れない。

## 10. 【仮定】
- 期間の既定は直近28日、選べるのは直近7日・28日・90日（仕様案 §4 の既定に合わせる）。前の期間は同じ長さの直前の期間。
- 「定義」はダイアログではなく、カードの下で開閉する。
- 定義の要約の「7日」は、SC-A07 で決めた今の値を出す。
- 気づきは I-01〜I-06 の番号順で条件を満たすものから3件。リンク先は I-01・I-02・I-05 → SC-A03、I-06 → SC-A04。I-03（店の期限切れ）は観光協会の画面に店ごとの詳しい画面が無いため、リンクを付けない（SC-A10 は店舗の画面）。I-02 のリンクは 15:45 にモックへ追加。
- 空・エラーの文言。
- 店舗の役割でこの画面を開いたときの表示（「この役割では使えない画面です」）。
- 期間を替えたときの `role="status"` のお知らせ。
