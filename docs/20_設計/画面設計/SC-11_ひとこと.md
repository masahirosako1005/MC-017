# SC-11 ひとこと（画面設計）

作成: 2026-11-09 15:06（実測） / 到達点: M3 / モック: `docs/10_企画/画面モック/SC-11_ひとこと.html`（1対1。見た目の正は `index.html#note`。空で送ったときのエラーと相棒の `<img>` の見本を足した）
上流: 方向性 §6・§9・§11・§19.6、要件定義 R-014・R-057、ADR-004・ADR-006。

## 1. 目的
スポットの感想を100字まで書いて残す。書くと、このスポットで1日1回さいころが増え、すごろくへ進む。**「書いたひとことは、次に来たときに見返せるよ」**（再訪の因果。見返しは Should の R-048）。

## 2. 対応
| 種類 | 番号 |
|------|------|
| 要件 | R-014（1〜100字・注意・＋1・ほかの人に見せない）、R-057（個人情報を書かない案内）、R-053（二重送信）、R-052（サーバーの検証）、R-055。Should: R-048（見返す） |
| ストーリー | US-018（Should: 見返しは US-018 の再訪の部分） |
| 受け入れ基準 | AC-018（画面側）、AC-019、AC-020（画面側）、AC-060（画面側）、AC-064 |

- 下のメニューは出さない（サブ画面）。

## 4. 状態
| 状態 | 画面 | 次の行動 |
|------|------|----------|
| 読み込み中 | 送信中はボタンが押せない | 待つ |
| 空（何も書いていない） | 字数「0 / 100字」。送ると #7 のエラー | 書く |
| エラー | 入力のエラーは #7。送信の失敗は「サーバーにつながりません…」か「うまくいきませんでした…」と「もう一度」。400（サーバーの検証）は「1〜100字で書いてね」【仮定】 | 直して送る |
| オフライン | 同じ PC のサーバーに送るので、ネットが切れても送れる。**地図が無いので「オフライン表示中」は出さない** | そのまま使う |
| 送った | 「ひとことを残しました。さいころ＋1」のお知らせを出して SC-05 へ。今日すでに書いていたら「ひとことを残しました」だけ（回数は増えない） | SC-05 |

## 8. アクセシビリティ（WCAG 2.2 AA）
| 達成基準 | 確認の観点 |
|----------|------------|
| 1.3.1 / 3.3.2 | 入力欄に `<label for>`、字数と注意を `aria-describedby` |
| 1.3.5 | 個人の情報を集める欄ではないので `autocomplete` は対象外（`autocomplete="off"` は付けない） |
| 1.4.3 | 入力欄の枠（#EDE2D1）は飾り、フォーカス時の枠（#0E7C74）と影で 3:1 を M4 で計算 |
| 2.4.7 | フォーカスで枠の色と影が変わる |
| 2.4.11 | 下の「送る」とキーボードの表示で、入力欄が隠れない |
| 3.3.1 | 空で送るとエラーの文が入力欄に結び付く（`role="alert"`・`aria-invalid`） |
| 3.3.3 | 「ひとことを書いてから送ってね」「1〜100字で書いてね」で直し方を示す |
| 4.1.3 | 字数を `aria-live="polite"` で |

- 使いにくくなる人と対策（INC-01）: 書いてよいことが分からない子ども→注意の帯。字数が見えにくい人→字数の通知。
- だれのための工夫か（INC-03）: 「名前や連絡先は書かないでね」は子ども（P-06）のためだが、だれの個人情報も守る。

## 9. M4 の E2E で確かめる観点
- 1〜100字で送ると SC-05 でさいころ ＋1。空で送るとエラーで送られない（AC-018 の画面側）。
- `<img src=x onerror=alert(1)>` などを送っても、ダイアログもスクリプトも動かない（AC-019）。
- 送るを素早く2回押しても1回分だけ（AC-060 の画面側）。

## 10. index.html との違い
1. 相棒は仮の猫の絵ではなく `<img>`（§18）。

## 11. 【仮定】
- 字数はコードポイントで数える（実装の `charCount`）。
- サーバーの 400 の文言。
- 「もどる」で書きかけを残さない。
