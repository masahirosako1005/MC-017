# SC-A03 再訪の因果（画面設計）

作成: 2026-11-09 15:33（実測） / 位置づけ: 追加企画（運営画面）。要件定義へは未反映 / モック: `docs/10_企画/画面モック/SC-A03_再訪の因果.html`（1対1。見た目の正は `admin.html#a03`）

## 1. 目的
**「どうしたら再訪につながるか」**に、再訪の因果（体験 → 気持ち → 次に来る理由 → 再訪）の**どの段で人が減っているか**で答える。あわせて、どの「次に来る理由」を持って帰った人がよく戻っているか（K-04）と、戻らなかった人が盤のどこで止まったか（K-09）を見せ、打ち手（🎁の間隔・理由の出し方）を考える材料にする。年代・一緒に来た人・段差少なめ・アバターで絞り、旅行者の違いごとの差を見る。

- 多様な旅行者（INC-02）: 年代・一緒に来た人・段差少なめ・アバターで絞れるので、高齢者や家族連れなど旅行者ごとの減り方の違いが見える。

## 9. 試験で確かめる観点（仕様案 §9 から。合否は書かない）
- 指標の計算: 決まった小さいデータで、各段の人数・K-04（理由ごとの再訪率と「どれも無い」）・K-09 が手計算と一致する。旅の2日目を再訪に数えない。前の訪問から7日ちょうどは再訪、6日は再訪でない。
- 段の人数が上から減るだけになる（前の段を通っていない人を数えない）。
- 個人情報: 応答に `guest-` と CSV の7桁 ID が含まれない。絞り込みで5人未満になったマスが数字で出ない。
- 入力: `age=70s`・`companion` の配列・未知のキー・期間の逆転・367日以上が 400。
- 権限: 店舗の役割で 404、`ADMIN_MODE` なしで 404。
- アクセシビリティ: 棒と同じ数字が表にある、キーボードだけで絞り込める、200% 拡大で横に流れない。

## 10. 【仮定】
- 各段は「前の段も通った人」だけを数える（厳密な段）。
- 絞り込みは選ぶとすぐ読み直し、「適用」ボタンを置かない。読み直したら `role="status"` で伝える。
- 年代・一緒に来た人が未回答の利用者は「すべて」のときだけ数え、「未回答」の選択肢は置かない。
- 止まり位置は盤の番号（1枚目・2枚目）を分けず、最後の盤の `pos` を10マスごとに数える。「多い」は全体の20%以上（I-05 と同じ）。
- 期間の終わり近くに来た人も分母に入れ、まだ再訪できないことは注記で伝える。
- 空・エラー・5人未満で表を出さないときの文言。
