# SC-07 特典（画面設計）

作成: 2026-11-09 15:06（実測） / 到達点: M3 / モック: `docs/10_企画/画面モック/SC-07_特典.html`（1対1。見た目の正は `index.html#perks` と `#use`（使う確認）。index.html に無い「期限切れ」と「空」の見本を足した）
上流: 方向性 §6「特典」・§13（C4・C5）・§19.10、データ設計 §2.3・§3（coupons）、要件定義 R-024〜R-026。

## 1. 目的
すごろくの🎁マスとゴールで手に入れたクーポンを、**使い方・使えるお店・期限が一目で分かる形**で見せ、お店で確認をはさんで使う。「次に来た日から使える」クーポンが、次に来る理由になる。

## 2. 対応
| 種類 | 番号 |
|------|------|
| 要件 | R-024（スタンプの数・クーポンの3つの状態・使い方・お店・期限）、R-025（確認を1回・戻せない）、R-026（次に来た日から）、R-053（二重送信）、R-055 |
| ストーリー | US-002、US-003、US-009 |
| 受け入れ基準 | AC-031、AC-032（画面側）、AC-033（画面側）、AC-060（画面側）、AC-064 |

## 3. 要素（上から順）
| # | 要素 | 内容・ルール | データ |
|---|------|--------------|--------|
| 1 | ヘッダー | h1「特典」、右に設定 | — |
| 2 | 説明 | 「お店で画面を見せて『使う』を押してね」 | — |
| 3 | スタンプの数 | カードに、取ったスタンプのアイコン（最大4つ、傾けた丸）と「取ったスタンプ n こ」 | API 11 `stamps` |
| 4 | クーポン（チケットの形のカード） | 並び: 新しいもの→使える→次に来た日から→利用済み→期限切れ【仮定】。各カード: アイコン（使える=プレゼント、次に来た日から=鍵）、名前、状態のチップ（「使える」主色／「次に来た日から」金／「利用済み」灰／「期限切れ」灰）、新しいものに赤い「NEW」。切り取り線の下に「使えるお店」「期限」（使えるものは「使い方: お会計の前に、この画面をお店の人に見せてね」も）。使えるものは「使う」（金のボタン 48px）。次に来た日からは鍵と「（日付）以降に来たら使えます」。利用済みは「利用済み」のはんこ（飾り。チップと同じ文字） | `coupons` |
| 5 | 使う確認（下から出るダイアログ） | 「使う」で、暗い幕の上に下から: h2「この特典を使いますか？」、クーポン名とお店、「お店の人に画面を見せてから押してね。使うと元に戻せません。」、［使う］（主ボタン）［やめる］（白）。開くと［使う］にフォーカス、Esc・幕の外・［やめる］で閉じて「使う」ボタンへフォーカスを戻す。［使う］で送信し、利用済みにして「利用済みにしました」のお知らせ | API 12 |
| 6 | 下のメニュー | 特典（`aria-current="page"`） | — |

- 「NEW」は特典の画面で一度見たら消える（`seen`）。
- 期限・使える日はアプリ内の今日で決める（サーバーが状態を返す）。

## 4. 状態
| 状態 | 画面 | 次の行動 |
|------|------|----------|
| 読み込み中 | スタンプのカードとクーポンの場所に灰色の枠と「読み込み中…」 | 待つ |
| 空（クーポン0枚） | 「まだ特典はありません。すごろくの🎁マスに止まると もらえるよ。」とボタン「すごろくで遊ぶ」→ SC-05【仮定】 | SC-05 |
| エラー | 一覧の失敗:「うまくいきませんでした…」と「もう一度」。使うの失敗（409: 使えない・済み）:「この特典は いま使えません」と一覧を取り直す | もう一度 |
| オフライン | 同じ PC のサーバーなので、ネットが切れても見せて使える。**地図が無いので「オフライン表示中」は出さない** | そのまま使う |
| 送信中 | ［使う］は押せない（`aria-disabled`）。素早い2回押しでも1回だけ | 待つ |
| 使った後 | カードが利用済み（灰色・はんこ）、お知らせ | — |
| 期限切れ | 灰色のカード、チップ「期限切れ」、「使う」は出さない | — |

## 8. アクセシビリティ（WCAG 2.2 AA）
| 達成基準 | 確認の観点 |
|----------|------------|
| 1.1.1 | アイコン・はんこは `aria-hidden`（状態はチップの文字） |
| 1.3.1 | クーポンは `<article>`、お店・期限は `<dl>` |
| 1.4.1 | 状態は色だけでなくチップの文字と鍵・はんこの形 |
| 1.4.3 | 「NEW」（白／#D2402A）、チップの文字を M4 で計算 |
| 2.1.2 | 確認ダイアログから Esc で出られる |
| 2.4.3 | ダイアログを開くと中へ、閉じると「使う」へフォーカスが戻る |
| 2.4.11 | 下から出るダイアログが、フォーカスした要素を隠さない（ダイアログの中だけを Tab で回る） |
| 2.5.8 | 「使う」48px、［使う］［やめる］58px |
| 3.3.4 | 戻せない操作の前に確認を1回（R-025） |
| 4.1.2 | ダイアログは `role="dialog"` `aria-modal="true"` `aria-labelledby` |
| 4.1.3 | 「利用済みにしました」を `role="status"` で |

- 使いにくくなる人と対策（INC-01）: 押し間違えやすい人→確認を1回。急いでいる人→使い方・お店・期限をカードに全部書く。
- だれのための工夫か（INC-03）: 確認は高齢者（P-03）のためだが、子どもを見ながらの親（P-01）にも効く。

## 9. M4 の E2E で確かめる観点
- スタンプの数と、クーポンが「使える／次に来た日から／利用済み」で並び、使い方・お店・期限が書いてある（AC-031）。
- 「使う」→確認→［使う］で利用済み。［やめる］・Esc では変わらない（AC-032 の画面側）。
- 次に来た日からのクーポンは「使う」が無く、日付が書いてある。デモで＋7日にすると「使う」が出る（AC-033 の画面側）。
- ［使う］を素早く2回押しても1回だけ（AC-060 の画面側）。

## 10. index.html との違い
1. 「期限切れ」の状態を足す（API の `status: 'expired'`）。
2. 空（0枚）の状態を足す。

## 11. 【仮定】
- クーポンの並び順（新しい→使える→次に来た日から→利用済み→期限切れ）。
- 空のときの文言とボタン。
