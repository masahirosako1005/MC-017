# SC-04 スポット詳細（画面設計）

作成: 2026-11-09 12:44（実測） / 更新: 2026-11-09 15:06（実測。M3 で確定） / 到達点: M3 / モック: `docs/10_企画/画面モック/SC-04_スポット詳細.html`（1対1。見た目の正は `index.html#detail`、ADR-002。モックは iframe と、index.html に無い「予言の場所」の見本）
上流: 方向性 §6「スポット」・§7・§13（C3・C6）・§19.4、補強案 案B、要件定義 R-012〜R-016・R-031。

## 1. 目的
スポットの中身を知り、**その場でさいころが増える行動（QR・ひとこと・誘う）**へ進む画面。あわせて「次に来る理由」（予言の答え合わせ・近くのお店・みんなのひとこと・季節のイベント）を見せる。

## 2. 対応
| 種類 | 番号 |
|------|------|
| 要件 | R-012（架空のイベント・段差・実在施設の注記・きっかけ3つの状態）、R-013（QR の入口）、R-014（ひとことの入口）、R-015（誘うの入口）、R-016（近くのお店・みんなのひとこと）、R-031（予言の場所の案内）、R-055 |
| ストーリー | US-001、US-004、US-012、US-015 |
| 受け入れ基準 | AC-016、AC-022（画面側）、AC-040（画面側の案内）、AC-064 |

## 3. 要素（上から順。index.html の detail に合わせる）
| # | 要素 | 内容・ルール | データ |
|---|------|--------------|--------|
| 1 | ヘッダー | 左に「もどる」（48px）、h1 はスポット名、右に設定 | マスタ |
| 2 | 絵（ヒーロー） | 淡い主色の角丸の枠に、スポットのアイコン（白い丸、`aria-hidden`）。左上に分類と季節のチップ | マスタ `icon`・`cat`・`season` |
| 3 | イベントのカード | 小見出し「イベント（架空）」、イベント名、一言、チップ「段差少なめ」か「段差あり」 | マスタ `ev`・`short`・`stepFree` |
| 4 | 実在施設の注記 | 実在の位置の施設だけ「施設は場所だけ実在です。営業時間などは施設の公式の案内を見てね。」 | マスタ `real` |
| 5 | 予言の場所（あるときだけ。index.html に無い） | このスポットが open の予言のとき、金の点線の枠のカード: h2「（相棒の名前）の予言の場所」、「前の旅で『次は（季節）の（時間帯）、ここが気に入るはず』と予言したよ」、理由（3つまで、強さの文字つき）。**再訪の日**なら「ここで QR を読むと答え合わせ。さいころ2回」、旅の2日目・初日は「答え合わせは、次に来た日（前回から7日以上あけた日）にできます」 | API 14 `ProphecyState.current`・`MeState.visitKind` |
| 6 | ほかにも さいころが振れること | h2。カード2つ（76px、＞つき）: 「ひとことを書く」→ SC-11、「友達を誘う」→ SC-08。まだなら金のチップ「＋1 さいころ」、済んだら灰色のチップ「✓ 今日は済み」（押すと「今日は済み」のお知らせ） | `MeState.doneToday[spotId]` |
| 7 | 近くのお店 | h2。説明「レジ横のQRを読んでも さいころが振れます。」、レジ横 QR のあるお店を直線距離の近い順に最大3件（アイコン・名前・分類・「約 n m」）。行は押せて、そのお店の詳細（SC-04）へ【仮定】。下に「距離はまっすぐ測った長さです。」 | マスタの緯度経度（`nearbyShops`） |
| 8 | みんなのひとこと | h2。「ダミーの見本です」、2件（年代・一緒に来た人のチップと文）。**自分のひとことは出さない** | マスタ `voices` |
| 9 | 架空の注記 | 「スポットの内容とイベントは架空です（一部の施設は位置のみ実在）。」 | — |
| 10 | 下の操作（1つだけ） | QR がまだ:「QRスタンプを読む ＋1」（主ボタン）→ SC-10。済み:「すごろくで遊ぶ」（金のボタン）→ SC-05 | `doneToday` |

- **ひとことの入力欄はこの画面に置かない**（SC-11）。友達を誘うも下の操作には置かず、#6 のカードから SC-08 へ。
- 下のメニューは出さない（サブ画面。方向性 §19.1）。
- **1スポット1日1回**はきっかけ（QR・ひとこと・誘う）ごと。回数はサーバーが決めて記録し、画面は `doneToday` を出すだけ。

## 4. 状態
| 状態 | 画面 | 次の行動 |
|------|------|----------|
| 読み込み中 | スポットの中身はマスタなので即座に出る。`doneToday` を取り直す間、#6 のチップの場所に「読み込み中…」【仮定】 | 待つ |
| 空（見つからない） | 無いスポット ID のとき「このスポットは見つかりませんでした」と「スポットにもどる」 | SC-03 へ |
| エラー | 取り直しの失敗:「うまくいきませんでした。少し待ってから もう一度ためしてね。」と「もう一度」 | もう一度 |
| オフライン | サーバーは同じ PC なので、ネットが切れても QR・ひとこと・誘うは使える。**地図が無いので「オフライン表示中」は出さない** | そのまま使う |
| QR を読んだ後 | 下の操作が「すごろくで遊ぶ」 | SC-05 |
| 今日はぜんぶ済み | #6 が2つとも「✓ 今日は済み」、下の操作は「すごろくで遊ぶ」 | 近くのお店・ほかのスポット |
| 予言の場所（再訪の日） | #5 に「ここで QR を読むと答え合わせ」 | QR を読む → SC-10 → SC-09 表示B |
| 予言の場所（再訪の日でない） | #5 に「答え合わせは、次に来た日にできます」 | — |

## 8. アクセシビリティ（WCAG 2.2 AA）
| 達成基準 | 確認の観点 |
|----------|------------|
| 1.1.1 | ヒーローのアイコンは飾り（スポット名は h1 にある）。チップの印（チェック）は `aria-hidden` で文字が意味を持つ |
| 1.3.1 / 2.4.6 | h1（スポット名）→ h2（予言の場所・ほかにも…・近くのお店・みんなのひとこと） |
| 1.4.1 | 「＋1 さいころ」「✓ 今日は済み」を文字で。段差は「段差少なめ／段差あり」の文字 |
| 1.4.3 / 1.4.11 | チップ（#6B4A00／#FFF1D2、#62625D／#EEEDE9）を M4 で計算 |
| 1.4.10 | 幅 320px・文字「大」で横スクロールなし |
| 2.4.11 | 下の操作ボタンに、フォーカスした要素（みんなのひとことの最後など）が隠れない |
| 2.5.3 | カードの名前に「ひとことを書く」「友達を誘う」を含む |
| 2.5.8 | カード 76px、お店の行 44px 以上、下のボタン 58px |
| 4.1.3 | 「今日は済み」のお知らせは `role="status"` |

- 使いにくくなる人と対策（INC-01）: 段差が苦手な人→段差の表示を詳細の上の方に。日本語が読めない人→English。
- だれのための工夫か（INC-03）: 段差の表示は車いすの人（P-04）のためだが、ベビーカー・高齢者にも効く。

## 9. M4 の E2E で確かめる観点
- 架空のイベント・段差・実在施設の注記・ひとこと／誘うの状態（＋1 か 今日は済み）と、下の「QRスタンプを読む」が出る（AC-016）。
- QR の後は下の操作が「すごろくで遊ぶ」に替わる（AC-016・AC-017 の画面側）。
- 近くのお店が近い順で最大3件、みんなのひとことに自分のひとことが出ない（AC-022 の画面側）。
- 予言の場所で、旅の2日目には「答え合わせは、次に来た日にできます」（AC-040 の画面側）。

## 10. index.html との違い
1. 「予言の場所」のカードを足す（index.html に予言は無い。SC-09）。
2. 近くのお店の行を押せるようにする（index.html は押せない行）。

## 11. 【仮定】
- 近くのお店の行はそのお店の詳細へ移る。
- 予言の場所のカードはイベントのカードと「ほかにも…」の間。
- `doneToday` の取り直し中だけチップの場所に「読み込み中…」。
