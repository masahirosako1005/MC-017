# SC-A10 店舗ダッシュボード（画面設計）

作成: 2026-11-09 15:34（実測） / 位置づけ: 追加企画（運営画面）。要件定義へは未反映 / モック: `docs/10_企画/画面モック/SC-A10_店舗ダッシュボード.html`（1対1。見た目の正は `admin.html#a10`）
上流: 運営向け画面_仕様案 §2（店舗は自店だけ）、§4（K-07・K-11、小さい数を隠す）、§5（SC-A10・Must）、§5.1、§7（US-106）、§8（`/api/admin/shops/:shopId/summary`・`demand`）、§9、§11.3（近くで予定が増えている印）、§11.7（効果）。

## 1. 目的
店長の「**割引に見合う客が来ているか**」（US-106）と、「**どうしたら次も来てもらえるか**」に答える画面。自店のクーポンが何枚出て何枚使われたかに加え、**次回クーポンを使いに戻った人数**（再訪の因果の最後の段）と、**どのスポットから寄ってくれたか**を見せる。近くで次回の予定が増えていれば知らせ、SC-A13 で先回りの特典マスを作る入口にする。ほかの店の個別の数字は見せない。

## 4. 状態
| 状態 | 画面 | 次の行動 |
|------|------|----------|
| 読み込み中 | カードと表の場所に灰色の枠と「読み込み中…」。数字は前の役割の値を出さない | 待つ |
| 空（期間内に自店のクーポン0枚） | カードは「0枚」「0人」「0回」を出し、表の代わりに「この期間に使われたクーポンはありません。期間を広げるか、『自店のクーポン』で止めていないか確かめてください。」とリンク「自店のクーポン」→ SC-A11【仮定】 | 期間を変える・SC-A11 |
| 空（店の特典マス0件） | 効果の表の代わりに「まだ店の特典マスはありません。『近くの予定と特典マス』で作れます。」とリンク → SC-A13 | SC-A13 |
| エラー | 「数字を読み込めませんでした。」と「もう一度」。知らせの帯（demand）だけ失敗したときは帯を出さず、ほかは出す | もう一度 |
| オフライン | 同じ PC のサーバー（127.0.0.1）なので、ネットが切れても見られる。表示は変えない | そのまま使う |
| 5人未満 | 人数・枚数のマスを「5人未満」（数字と棒を出さない） | — |
| 30人未満 | K-11 の値の横に「参考」。因果とは言い切らない | — |
| 知らせなし | 増えている印のスポットが無ければ帯を出さない | — |
| 権限なし | `ADMIN_MODE` なしは 404。店舗の役割で**他店の `shopId`** を指定すると 404（他店があることも分からない）。観光協会からこの画面への入口は作らない【仮定】（API は仕様案 §8 のとおり観光協会も呼べる） | SC-A01 |

## 8. アクセシビリティ（WCAG 2.2 AA）
| 達成基準 | 確認の観点 |
|----------|------------|
| 1.1.1 | 時間帯の棒は飾り（`aria-hidden`）で、同じ数字を「枚数」の列に持つ |
| 1.3.1 | 表は `<caption>`、列の見出し `th scope="col"`、行の見出し `th scope="row"`（時間・スポット・キャンペーン）。カードは名前と値が読み上げで続く（例「配ったクーポン 128枚 12枚増えた」） |
| 1.4.1 | 差は色（緑・赤）だけでなく ▲▼＝の記号と、読み上げ用の「増えた」「減った」「変わらず」【仮定】。キャンペーンの状態はチップの文字。「5人未満」「参考」は文字 |
| 1.4.3 | 知らせの帯（#3B2A00／#FFF1D2）、チップ「実施中」（#1F6E3A／#E3F3E7）、灰色の「5人未満」（#55625F／白）を M4 で計算 |
| 1.4.4・1.4.10 | 768px のタブレットと 200% 拡大で、カードが折り返し、表が横に流れない |
| 2.4.4 | リンク「特典マスを作る」は帯の文と同じ段落にあり、行き先が分かる |
| 2.4.7・2.4.11 | フォーカスの枠が見え、上の帯（固定）に隠されない |
| 2.5.8 | リンク・期間の選択・「定義」は 44px 以上 |
| 4.1.3 | 知らせの帯は `role="status"`（開いたときに読み上げる） |

- 使いにくくなる人と対策（INC-01）: 数字に慣れていない店主→カードの名前を「配った」「使われた」「戻った人」のやさしい言葉にし、割合はカードの中に1つだけ。
- だれのための工夫か（INC-03）: 768px で崩れない並びはレジ横のタブレットで使う店主のためだが、拡大して読む高齢の店主にも効く。

## 9. 試験で確かめる観点（仕様案 §9 から。合否は書かない）
- 指標の計算: 決まった小さいデータで、配った・使われた・まだ使えない・再訪の日に使った人（旅の2日目 `day2` に使った分を数えない、再訪の日だけ）・期限切れが手計算と一致する。
- 権限: 店舗の役割で他店の `shopId`（例 `shop-s8` で `s9`）を指定すると 404。`shopId` が許可リスト外（`s1`）は 400 か 404。`ADMIN_MODE` なしで 404。
- 個人情報: 応答に `guest-` と CSV の7桁 ID が含まれない。5人未満のマス（時間帯・スポット・K-11）が数字で出ない。エリア全体は合計だけで、他店の個別の値が応答に無い。
- 入力: 期間の逆転・367日以上・未知の query・配列の query（`?from[]=`、同名の2つ指定）が 400。
- 店の特典マス: K-11 の「止まった」「使った」が `board_extras`・`coupons.campaign_id` の件数と一致し、承認前（pending・rejected・draft）のキャンペーンが表に出ない。
- アクセシビリティ: 棒と同じ数字が表にある、差に記号がある、768px と 200% 拡大で横に流れない。

## 10. 【仮定】
- 知らせの帯は、増えている印のスポットがあるときだけ出し、複数なら人数の多い1つ。5人未満なら人数を書かない。
- 時間帯は 2時間ごとの枠で、使われた枠だけ出す。5枚未満の枠は「5人未満」（1人1枚に近いため人数と同じ扱い）。
- 同じ日に寄ったスポットは、5人未満のスポットを「そのほか」にまとめる。
- カードの数え方（4a）。とくに「まだ使えない」は、あかり堂ではゴール特典・季節の1品の型が無いため、店の特典マスのクーポンだけで数える。「再訪の日に使った人」は型を問わず再訪の日に使った人。
- K-11 の表は承認された（approved・active・ended・stopped）キャンペーンだけ、新しい順。
- 各カードに「定義」ボタンを置く（仕様案 §5.1。15:45 にモックへ追加）。
- 観光協会からこの画面を開く入口は作らない。
- 空のときの文言とリンク。
