## 1. 目的
「**何に困っているか**」「**どうしたら再訪につながるか**」の答えを**信じてよいか**を確かめる画面（US-108）。分析の元になる CSV が何行読まれ、何行が取り込まれ、何行がどんな理由で除かれたか、元データの中の食い違い（13 と 18 の不一致 227人）をどう扱ったかを見せる。元の CSV は読むだけで、書き換えない。

## 4. 状態
| 状態 | 画面 | 次の行動 |
|------|------|----------|
| 読み込み中 | 表の場所に灰色の枠と「読み込み中…」 | 待つ |
| 空（取込の記録0件） | 「まだ CSV を取り込んでいません。サーバーを起動すると、SAMPLE_DATA_DIR のフォルダから取り込みます。」【仮定】。食い違いの表も出さない | サーバーを起動し直す |
| エラー（読み込み） | 「データの状態を読み込めませんでした。」と「もう一度」 | もう一度 |
| 取込に失敗したファイル | その行の「除いた理由」に ⚠ と文字で理由（例「列名が違うため取り込んでいません」「UTF-8 として読めませんでした」）。取り込んだ数は 0 | CSV を確かめてサーバーを起動し直す |
| 除いた行がある | 「除いた」に数字、「除いた理由」に理由ごとの件数 | 必要なら元データを確かめる |
| オフライン | 同じ PC のサーバー（127.0.0.1）なので、ネットが切れても見られる。表示は変えない | そのまま使う |
| フォルダが無い | `SAMPLE_DATA_DIR` のフォルダ・ファイルが無いときはサーバーが起動しないので、この画面は開かない（データ設計 §4.1 の文をサーバーが出して止まる） | フォルダを確かめる |
| 権限なし | `ADMIN_MODE` なしは 404。店舗の役割でこの API を呼ぶと 404。店舗のメニューにこの画面は出ない | SC-A01 |

- 使いにくくなる人と対策（INC-01）: データに慣れていない担当→「除いた理由」を記号でなく文で書き、扱い（どちらを正にしたか）も同じ表に書く。

## 9. 試験で確かめる観点（仕様案 §9 から。合否は書かない）
- 個人情報: 応答に `guest-`、CSV の7桁 ID、名前・メール・LINE ID、行の中身が含まれない。食い違いは人数だけ。
- データ: 決まった小さい CSV で、読んだ行・取り込んだ・除いた・理由ごとの件数が手で数えた値と一致する。同じ CSV を2回取り込んでも件数が増えない。
- 食い違い: 13 の集計列と 12・18 の件数が合わない人数が、決まったデータで手で数えた値と一致する（実データではデータ調査の 0人・227人）。
- 入力: query を付けた要求・配列の query が 400。
- 権限: 店舗の役割で 404、`ADMIN_MODE` なしで 404。
- エラー: 応答にファイルのパス・スタック・SQL が含まれない。
- アクセシビリティ: 表の見出しが読み上げられる、200% 拡大で横に流れない。

## 10. 【仮定】
- 08・09 は取込を作るまで「読んだ行」だけを出し、「取り込んだ」「除いた」は「―」にする（15:45 にモックを直した）。
- 読んだ行を出すために、取込を作る前でも 08・09 の行数だけ数えて `import_log` に残す（中身は DB に入れない）。
- 08 の取込を作った後、「その他」に数えた要望の件数を表の下に出す（仕様案 §3。モックに無い）。
- 画面から取込を始めるボタンは作らない（起動時だけ）。
- 空のときの文言。
- 応答に CSV の置き場所のパスを含めない。
- この画面では上の帯の期間の選択を使わない。
