# SC-A13 近くの予定と特典マス（画面設計）

## 1. 目的
店長の「**どうしたら次の旅でも店に寄ってもらえるか**」に、**客が来る前に**答える画面（US-110・US-111）。近くのスポットに「次に行く予定」を入れている旅行者の人数と季節・時間帯を見せ、人数が多いときに自店のイベント・クーポンを作って、その人たちのすごろくの少し先に「お店の特典マス」🏪 として出す。止まった旅行者は翌日から使えるクーポンを持ち帰るので、「予定のスポットのついでに店へ寄る」という**次に来る理由**が生まれる（§11.1 の再訪の因果）。集計の後追いではなく、先の需要に合わせて動けるのがこの画面の価値。

- 置き方（§11.5）: 対象者のいまの盤で、いまの位置の3〜10マス先の「ふつうのマス」のうち `(利用者 ID とキャンペーン ID から作る数) mod 候補の数` 番目。1枚の盤に店のマスは3つまで。🎁・スポット・季節・ゴール・ほかの店のマスを置き換えない。置いたマスは `board_extras` に保存し動かさない。止まったとき、振る処理と同じトランザクションで「配った枚数 < 上限」を確かめて1枚出す（`UNIQUE(user_id, campaign_id)`）。使えるのは手に入れた翌日からキャンペーンの最終日まで。

## 4. 状態
| 状態 | 画面 | 次の行動 |
|------|------|----------|
| 読み込み中 | 予定の表とキャンペーンの表の場所に灰色の枠と「読み込み中…」。「確認に送る」は押せない | 待つ |
| 空（近くの予定0件） | 予定の表の各行が「5人未満」。表の下に「近くのスポットに次回の予定はまだ少ないです。旅行者がスポットから予定を入れると、ここに人数が出ます。」【仮定】。6d は「あと5人以上で作れます」 | 下書きを作って待つ |
| 空（キャンペーン0件） | キャンペーンの表の代わりに「まだキャンペーンはありません。」 | 上のフォームで作る |
| エラー（読み込み） | 「予定の人数を読み込めませんでした。」「キャンペーンを読み込めませんでした。」と、それぞれ「もう一度」。片方だけ失敗したら、もう片方は出す | もう一度 |
| エラー（入力・400） | 欄の下に ⚠ と文字で直し方（「名前は1〜20字で書いてください」「URL・メール・電話番号は書けません」「始まる日は明日以降にしてください」「期間は7〜90日にしてください」「イベントの日は期間の中にしてください」「上限は1〜500の整数にしてください」）。送る前に画面でも同じ検査。先頭のまちがいにフォーカスを移し、件数を `role="alert"` | 直して送る |
| 2.5km の外 | 表に無いスポットを指定した要求は 400（画面からは選べない） | — |
| 閾値未満で作れない（409） | 6d が「あと n 人で作れます」か「あと5人以上で作れます」。「確認に送る」は `aria-disabled`。送った間に人数が減ったときの 409 は「対象が10人に届かなくなりました。人数を読み直しました」と出して表を取り直す | 下書きに保存・待つ |
| 同時に出せる数の上限（409） | 確認待ち・承認済み・実施中が合わせて2つあるとき、ボタンの近くに「同時に出せるのは2つまでです。終わるか、途中で止めてから作ってください」。「確認に送る」は `aria-disabled` | 終わるのを待つ・止める |
| 5人未満 | 人数・季節・時間帯のマスを「5人未満」。対象の合計に5人未満のスポットを含むときは「n人以上」 | — |
| 増えている | スポット名の横にチップ「増えています」 | 作る |
| 送信中 | 「確認に送る」「下書きに保存」「止める」は押せない（`aria-disabled`）。押した時の `requestId` で、2回押しても1件だけ | 待つ |
| 送った後 | 表の先頭に「確認待ち」の行が足され、フォームを空にする | 観光協会の確認を待つ |
| 差し戻し | チップ「差し戻し」と理由（観光協会が書いた1〜100字、文字のまま表示） | 直して作り直す |
| 実施中・配り終わり | 「配った ／ 上限」が上限に達したら、状態のチップの横に「配布は終わりました」【仮定】 | — |
| 止めた後 | チップ「止めました」、操作なし | — |
| デモ（DEMO_MODE） | 予定の表のキャプションの後ろに「（ダミーを含む）」（§11.9）。ダミーの予定は CSV の利用者から決まった計算で足したもの | — |
| オフライン | 同じ PC のサーバー（127.0.0.1）なので、ネットが切れても見て作れる。表示は変えない | そのまま使う |
| 権限なし | `ADMIN_MODE` なしは 404。店舗の役割で他店の `shopId`・他店の `campaignId` は 404。観光協会の役割で POST（作る・止める）は 404（仕様案 §8「その店の shop だけ」）。観光協会からこの画面への入口は作らない【仮定】 | SC-A01 |

## 9. 試験で確かめる観点（仕様案 §9・§9「店の特典マス」から。合否は書かない）
- 作れる条件: 対象が閾値ちょうど（10人）で作れ、9人では 409。2.5km の外のスポットを対象にすると 400。同時に出せる数（2つ）を超えると 409。
- 入力: 名前0字・21字、内容61字、改行を含む、始まる日が今日、期間6日・91日、上限0・501・1.5、割引4%・51%、値引き49円・1,001円、イベントの時間が 8:30 や 21:30、`kind='coupon'` でイベントの項目つき、未知キーが 400。URL・メール・電話番号の形（全角の「０５２－…」「ｗｗｗ．」を含む）が 400。XSS の文字列（`<img src=x onerror=…>`）は文字のまま表示される。
- 自店だけ（15:58 追加）: 本文に `shopId`・`shopIds`・`usableShops` を入れると 400。URL の店が自分と違うと 404。ほかの店の店名（全角・空白入りを含む）を名前・内容・品名に入れると 400。できたクーポンの「使えるお店」が自店の1つだけで、全部のクーポンで `coupons.shop_id` が `campaigns.shop_id` と一致する。「使える」を押せるのはそのクーポンの店のページだけ。画面に「使えるお店: あかり堂（自分の店だけ）」が文字で出て、選べない。
- 特典の例（15:58）: 「コーヒー1杯」の無料、100円引き、「アイス」のサービスが作れ、旅行者の画面に「コーヒー1杯 無料」「100円引き」「アイス サービス」と出る。品名0字・21字は 400。
- 置く場所: 同じ利用者・同じキャンペーンなら毎回同じマス。🎁・スポット・季節・ゴール・ほかの店のマスを置き換えない。いまの位置より後ろに置かない。1枚の盤に4つ目を置かない。
- 配る枚数: 上限ちょうどで次の人は「配布は終わりました」。同時に止まっても上限を超えない（トランザクション）。同じ人に2枚目が出ない。
- 使える日: 手に入れた当日と期限の翌日は 409、翌日から期限の日までは使える。
- 権限: 他店のキャンペーンの操作（止める・直す）は 404。店の役割では承認できない。承認前（確認待ち・下書き・差し戻し）は盤に出ない。観光協会の役割で作る・止めるは 404。
- 予定: 店への応答（demand）に利用者 ID が無く、5人未満のマスは数字が出ない。5人未満のスポットを含む合計が「n人以上」になる。
- 止める: 止めると新しく置かず、置いたマスが「終了」になり、配ったクーポンは期限まで使える。二重送信で記録が2行にならない。
- アクセシビリティ: 店のマスが 🏪 と店名の文字で分かる、6d の知らせが読み上げられる、キーボードだけで作って送れる、768px と 200% 拡大。

## 10. 【仮定】
- この画面は期間の選択を使わず、予定の人数は今日の時点の open で数える（`demand` に `from`・`to` を送らない。仕様案 §8 は `from`・`to` を書くが、予定は先の需要なので期間で切らない）。
- 前の週からの差は、どちらかの週が5人未満なら「―」。
- 5人未満のスポットを含む対象の合計は「n人以上」と出す（差し引きで5人未満の人数が分かるのを防ぐ）。作れるかの判定はサーバーが本当の人数で行うので、「作れます」に変わることで少しの手がかりは残る。
- SC-A08 で非公開のスポットは表と対象に出さない。
- 自店のクーポンだけ作れる（15:58 の指示）。使えるお店は固定表示で選べず、本文に店の項目を持たせない。ほかの店の店名を含む文は 400（マスタの店名と NFKC・空白除去で比べる。言い換えや略称までは見分けられないので、観光協会が SC-A14 で確かめる）。特典は「1品を無料・サービス／○円引き／○%引き」の3つで、旅行者の画面の表示名（「品名 無料」など）は辞書で作る。
- 種類の既定は「イベント」。クーポンの種類のときのチップは「お店のクーポン」。
- イベントの日は期間の中の1日。時間の選択肢は 9〜21時の決まった枠（辞書に置く）。
- 割引（%）・値引き（円）の入力欄（15:45 にモックへ「割引・値引きの値」の欄を追加）。
- 期間は両端を含めて数える（12/01〜12/31 は31日）。
- 文字の検査の細かい形（NFKC・URL・メール・電話番号の決め方・制御文字）。
- 同時に出せる2つに、承認済み（始まる前）も数える。下書きは数えない。
- POST の `draft`、下書きを直す PUT、「続きを書く」「直して作り直す」（15:45 に仕様案 §8 とモックへ追加）。
- 止めた後も、配ったクーポンは期限まで使える。止める確認は［やめる］に最初のフォーカス。
- キャンペーンの表は新しい順。上限に達したら「配布は終わりました」をチップの横に出す。
- プレビューのマスの番号は説明のための決まった見本。プレビューの盤は `<ol>` で作る。
- 観光協会からこの画面への入口は作らない。
- 空のときの文言。
