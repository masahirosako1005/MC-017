# SC-A08 スポットの公開と季節（画面設計）

作成: 2026-11-09 15:34（実測） / 位置づけ: 追加企画（運営画面）。要件定義へは未反映 / モック: `docs/10_企画/画面モック/SC-A08_スポットの公開と季節.html`（1対1。見た目の正は `admin.html#a08`）

16:17 の改訂: 管理サイトから「予言」をすべて外したため、「予言の候補」の列・外す理由・注記を、「公開」と「非公開にする理由」に置き替えた。

## 1. 目的
「**どうしたら再訪につながるか**」に答えるための土台を整える画面。休業・工事中のスポットを公開したままにすると、旅行者は「次はここ」と思って来たのに入れず、次に来る理由が裏切りに変わる。観光協会の担当が、**休業・工事のスポットを非公開にする**・**季節のイベントの期間を合わせる**ことで、盤・おすすめ・季節マスが「本当に行ける次の理由」であり続けるようにする。

## 4. 状態
| 状態 | 画面 | 次の行動 |
|------|------|----------|
| 読み込み中 | 表の場所に灰色の枠と「読み込み中…」。「保存」は押せない | 待つ |
| 空 | スポットはマスタの8か所で固定のため0件にならない。万一0件なら「スポットがありません。サーバーのマスタを確かめてください」【仮定】 | 管理者に知らせる |
| エラー（読み込み） | 「スポットの設定を読み込めませんでした。」と「もう一度」 | もう一度 |
| エラー（保存の入力） | 400 のとき、該当する行の入力の下に赤い字と ⚠ の記号で「期間は1〜120日にしてください」「実在する月日を選んでください」「非公開にする理由を選んでください」など。先頭のまちがいにフォーカスを移す。表の上に「入力を確かめてください（1件）」を `role="alert"` | 直して保存 |
| エラー（保存の衝突） | ほかのタブで先に保存されていたら（409）「ほかの画面で先に変更されました。最新の内容を読み直しました」と出し、表を取り直す【仮定】 | 確かめて保存し直す |
| オフライン | 同じ PC のサーバー（127.0.0.1）なので、ネットが切れても読み書きできる。表示は変えない | そのまま使う |
| 送信中 | ［保存する］は押せない（`aria-disabled`）。押した時に `requestId` を作り、2回押しても1回だけ保存（記録も1行だけ） | 待つ |
| 公開を外した行 | チェックが外れ、行に理由のチップ（「工事のため非公開中」など、色だけでなく文字） | — |
| 権限なし | `ADMIN_MODE` なしは `/admin`・`/api/admin/*` が 404。店舗の役割でこの API を呼ぶと 404（SC-A01 の設計に合わせる）。店舗のメニューにはこの画面が出ない | SC-A01 で役割を選び直す |

## 6. 使う API
| パス | いつ |
|------|------|
| GET `/api/admin/spot-settings`【仮定】 | 開いたとき・保存の後・409 の後。出力: スポットごとの `spotId`・`published`・`offReason`・`eventFrom`・`eventTo`・`version` |
| PUT `/api/admin/spot-settings`【仮定】 | ［保存する］。`z.strictObject({ requestId, items: [{ spotId, published, offReason, eventFrom, eventTo, version }] })`。`spotId` は s1〜s7・s10 の許可リスト、`items` は1〜8件、同じ `spotId` の重複は 400、`eventFrom`・`eventTo` は `MM-DD` の実在する日、`offReason` は `published=false` のときだけ必須。`version` が古ければ 409。観光協会だけ |

- 共通の決まり（`z.strictObject`・Origin 検査・`requestId`・`Cache-Control: no-store`・エラー形式）は `API設計.md` §1 と同じ。

## 9. 試験で確かめる観点（仕様案 §9 から。合否は書かない）
- 権限: 店舗の役割で GET・PUT `/api/admin/spot-settings` を呼ぶと 404。`ADMIN_MODE` なしでは `/admin` も `/api/admin/*` も 404。
- 入力: 未知キー・`spotId` が店（s8）や許可リスト外・`items` が0件か9件以上・同じスポットの重複・`02-30` のような無い月日・121日以上の期間・`published=false` で `offReason` が無い、が 400。
- 公開: 非公開にしたスポットが、利用者アプリの地図・一覧・おすすめコースに出ない。すでにある「次に行く予定」・スタンプ・クーポンは消えない。
- 公開: 非公開にしたスポットが SC-A13 の対象のスポットに選べない（2.5km 以内でも出さない）【仮定】。
- 二重送信: 同じ `requestId` の PUT を2回送っても、変更の記録が1行だけ。
- アクセシビリティ: キーボードだけで外して保存できる、チェックの名前にスポット名が入る、200% 拡大で横に流れない。

## 10. 【仮定】
- API `GET・PUT /api/admin/spot-settings` と表 `spot_settings`（`spot_id`・`published`・`off_reason`・`event_from`・`event_to`・`version`）は仕様案 §8・§11.8 に無いので足す。
- 「公開」を外したときの意味（利用者アプリの地図・一覧・コース・店の特典マスの対象から外す。スタンプ・予定・クーポンは消さない）。
- 公開が1か所も残らない変更は 409。
- 非公開にする理由の選択（工事・休業・そのほか）と、そのチップの文言。モックは「工事のため非公開中」のチップと、行を選んだときの見本。
- 期間の入力（月日の2つ、年をまたいでよい、1〜120日）。モックは行を選んだときの見本に入力を置く（15:45 に追加）。
- 変更は保存した直後から使い、`settings_history` と同じ形で記録する。
- 店（s8・s9・s11）は表に出さない。
- 同時に保存したときは `version` で 409 にして読み直す。
