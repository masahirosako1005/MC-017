# SC-A11 自店のクーポン（画面設計）

作成: 2026-11-09 15:34（実測） / 位置づけ: 追加企画（運営画面）。要件定義へは未反映 / モック: `docs/10_企画/画面モック/SC-A11_自店のクーポン.html`（1対1。見た目の正は `admin.html#a11`）
上流: 運営向け画面_仕様案 §2（店舗が変えられるもの）、§5（SC-A11・Should）、§5.1、§7（US-107）、§8（PUT `/api/admin/shops/:shopId/coupons/:templateId`）、§9。データ設計 §2.3（クーポンの型）。

## 1. 目的
「**何に困っているか**」の「操作と特典の受け取り方」（26件）につながる、**使えないクーポンで客をがっかりさせる**ことを防ぐ画面（US-107）。品切れや混む日に、店長が自店のクーポンの型を一時停止したり、1日に配る上限を決めたりする。止めている間は🎁マスに別のクーポンが出るので、旅行者のすごろくは止まらず、「次に来る理由」も消えない。

## 3. 要素（上から順）
| # | 要素 | 内容・ルール | データ |
|---|------|--------------|--------|
| 0 | 共通の枠 | 上の帯（「店舗: 店名」・期間の選択・「役割を変える」）、見本の注記、左のメニュー（「自店のクーポン」に `aria-current="page"`）。SC-A01 の設計と同じ。この画面は**期間の選択を使わない**（「今日」だけ）【仮定】 | — |
| 1 | 見出し | h1「自店のクーポン（店名）」 | 役割の店 |
| 2 | 説明 | 「品切れのときは一時停止できます。止めている間、🎁マスには別のクーポンが出ます。」 | — |
| 3 | クーポンの表 | 列「クーポン」（行の見出し）・「状態」・「一時停止」・「1日の上限」・「今日配った」。行は自店の型（`データ設計.md` §2.3）。あかり堂: お土産 10%オフ（souv10）／ちょうちん教室 100円引き（lantern）／あかり堂 ポストカード1枚（postcard）。きしめん ひだまり: きしめん 大盛り無料（kishimen）／天ぷら1品 サービス（tempura）／ゴール特典 きしめん1杯無料（goal）。みそかつ こもれび: みそかつ ミニ1切れ追加（minikatsu） | GET |
| 3a | 状態のチップ | 「配っています」（緑）／「止めています」（灰）／「今日の上限に達しました」（金）【仮定: 3つ目はモックに無い】。色だけでなく文字で分かる | `paused`・`dailyLimit`・`issuedToday` から計算 |
| 3b | 一時停止（チェック） | ラベル「止める」。入れると保存の後に新しく配らない | `paused`（boolean） |
| 3c | 1日の上限 | `type="number"`、ラベル「上限（枚）」、`min="0"` `max="999"`、空欄（placeholder「なし」）は上限なし（`null`）。整数だけ（小数・負の数・`1e2` のような指数の形・999 より大きい数は受け付けない）。0 は「今日は1枚も配らない」【仮定】 | `dailyLimit`（0〜999 か `null`） |
| 3d | 今日配った | アプリ内の今日に、この型を配った枚数（右寄せの数字） | `issuedToday` |
| 4 | 保存 | 主ボタン「保存」（44px）。変わった行だけを1行ずつ PUT で送る（行ごとに `requestId`）。全部できたら「保存しました」を `role="status"`。変わった行が無いときは押せない | PUT |
| 5 | 注記 | 「配ったクーポンは止めても使えます。店の特典マスのクーポンは『近くの予定と特典マス』で管理します。」 | — |

- 止めている間や上限に達した後の🎁マスは、**盤の並び（souv10 → kishimen → season → …）で次にある、配っている型**に替える。同じ店の別の型か、別の店の型になる（仕様案 §5 SC-A11）【仮定: 選び方】。全部の型が止まっていたら、その🎁マスはクーポンを出さず、利用者アプリに「いまは配れる特典がありません」と出す【仮定】。
- 季節の1品（season）は s10（大須 冬あかり横丁）の型なので、どの店の表にも出ない（店舗の役割は s8・s9・s11 だけ）。
- 変更は変更の記録（`settings_history` と同じ形）に残す【仮定】。

## 4. 状態
| 状態 | 画面 | 次の行動 |
|------|------|----------|
| 読み込み中 | 表の場所に灰色の枠と「読み込み中…」。「保存」は押せない | 待つ |
| 空 | 自店の型は1つ以上あるので0件にならない（s11 は1つ）。万一0件なら「この店のクーポンはありません」【仮定】 | — |
| エラー（読み込み） | 「クーポンの状態を読み込めませんでした。」と「もう一度」 | もう一度 |
| エラー（入力） | 上限が範囲外・整数でないとき、その欄の下に ⚠ と「0〜999 の整数か、空欄（上限なし）にしてください」。画面の中で送る前に調べ、サーバーの 400 でも同じ文 | 直して保存 |
| エラー（一部だけ保存できた） | 「2つのうち1つを保存できませんでした（ちょうちん教室 100円引き）。もう一度保存してください」を `role="alert"`。保存できた行はそのまま【仮定】 | もう一度保存 |
| オフライン | 同じ PC のサーバー（127.0.0.1）なので、ネットが切れても使える。表示は変えない | そのまま使う |
| 送信中 | 「保存」は押せない（`aria-disabled`）。2回押しても行ごとの `requestId` で1回だけ | 待つ |
| 止めています | チップ「止めています」、「止める」にチェック | 品が戻ったら外す |
| 上限に達した | チップ「今日の上限に達しました」。アプリ内の日付が変わると自動で「配っています」に戻る | — |
| 権限なし | `ADMIN_MODE` なしは 404。他店の `shopId`、または自店でない `templateId`（例 あかり堂で kishimen）は 404。観光協会の役割で PUT すると 404（仕様案 §8「その店の shop だけ」） | SC-A01 |

| 達成基準 | 確認の観点 |
|----------|------------|
| 1.3.1 | 表は列の見出し `th scope="col"` と行の見出し（クーポン名）`th scope="row"` を持つ |
| 1.3.1・3.3.2・4.1.2 | 「止める」のチェックと「上限（枚）」の入力に見えるラベル。行ごとに同じ名前が並ぶので、アクセシブルな名前にクーポン名を入れる（例「お土産 10%オフを止める」「お土産 10%オフの上限（枚）」）【仮定】。「空欄は上限なし」を `aria-describedby` で読む |
| 1.4.1 | 状態はチップの色だけでなく文字（「配っています」「止めています」「今日の上限に達しました」） |
| 1.4.3 | チップ「止めています」（#55544F／#ECEBE7）・「配っています」（#1F6E3A／#E3F3E7）を M4 で計算 |
| 1.4.4・1.4.10 | 768px のタブレットと 200% 拡大で、表が読める（表の枠の中だけ横に動く） |
| 2.1.1 | Tab でチェック・上限・保存に届き、Space でチェックを切り替えられる |
| 2.4.7・2.4.11 | フォーカスの枠が見え、上の帯（固定）に隠されない |
| 2.5.8 | チェックの行（`.chk`）・上限の入力・「保存」は 44px 以上 |
| 3.3.1・3.3.3 | 上限のまちがいを文字で知らせ、直し方（「0〜999 の整数か、空欄」）を書く |
| 4.1.3 | 「保存しました」は `role="status"`、一部の失敗は `role="alert"` |

- 一時停止は取り消せる（チェックを外して保存）ので、確認のダイアログは出さない（3.3.4 の対象外。ux ルール「取り消せるものは取り消せる」）。
- 使いにくくなる人と対策（INC-01）: レジで急いでいる店主→1つのチェックで止められ、保存を押すだけ。数字の入力は空欄のままでよい。
- だれのための工夫か（INC-03）: 止める機能は品切れに困る店主のためだが、使えないクーポンで店に来てがっかりする旅行者（操作と特典の受け取り方 26件）も守る。

## 9. 試験で確かめる観点（仕様案 §9 から。合否は書かない）
- 権限: 店舗の役割で他店の `shopId`・自店でない `templateId` を指定すると 404。観光協会の役割で PUT すると 404。`ADMIN_MODE` なしで 404。
- 入力: 未知キー・`paused` が文字列・`dailyLimit` が -1・1000・1.5・文字列・`requestId` なしが 400。`null` は受け付ける。
- 止めたとき: 止めた型の🎁マスに止まると、盤の並びで次の配っている型が出る（決まった計算で毎回同じ）。配ったクーポンは止めても使える。
- 上限: 上限ちょうどの枚数を配った後は、その日の次の人に別の型が出る。日付が変わると戻る。
- 二重送信: 同じ `requestId` の PUT を2回送っても、変更の記録が1行だけ。
- アクセシビリティ: チェックと上限の名前にクーポン名が入る、キーボードだけで止めて保存できる、200% 拡大。

## 10. 【仮定】
- API `GET /api/admin/shops/:shopId/coupons`（型ごとの状態と今日配った枚数）。仕様案 §8 は PUT だけ。
- 状態のチップ「今日の上限に達しました」（モックに無い）。日付が変わると自動で戻る。
- 上限 0 は「今日は1枚も配らない」、空欄は上限なし。
- 止めた・上限に達した型の替わりは、盤の並びで次にある配っている型。全部止まっていたらクーポンを出さず「いまは配れる特典がありません」。
- 「保存」は変わった行ごとに PUT を送り、一部の失敗はその行だけを知らせる。
- 変更を `settings_history` と同じ形で記録する。
- 注記の「近くの予定と特典マス」をリンクにする。
- この画面では上の帯の期間の選択を使わない。
