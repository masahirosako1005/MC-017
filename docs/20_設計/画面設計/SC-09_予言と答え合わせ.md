# SC-09 予言と答え合わせ（画面設計）

作成: 2026-11-09 12:47（実測） / 更新: 2026-11-09 15:06（実測。M3 で確定） / 到達点: M3 / モック: `docs/10_企画/画面モック/SC-09_予言と答え合わせ.html`（1対1。表示A と表示B を1ファイルに並べた。index.html に無い画面なので、index.html の色・角丸・部品に合わせて作り直した）
上流: 補強案 案B、方向性 §7（C1）・§8（C7）・§15、ADR-010（予言の計算）、データ設計 §7、要件定義 R-030〜R-034・R-047。

## 1. 目的
- **表示A 予言カード**: 相棒が「次に来たら気に入るはずの場所」を理由つきで示し、**次に来る理由**を作る。
- **表示B 答え合わせ**: 再訪の日に予言の場所へ来たことにごほうび（さいころ2回）を出し、「気に入った？」を聞いて、次の予言と相棒のかしこさに反映する。

## 3. 要素

### 表示A 予言カード
| # | 要素 | 内容・ルール | データ |
|---|------|--------------|--------|
| 1 | ヘッダー | 左に「もどる」、h1「（相棒の名前）の予言」（例「ともにゃんの予言」）、右に設定 | `avatar` |
| 2 | 相棒の吹き出し | 相棒の `<img>`（60px、alt「名前（わくわく）」）と吹き出し「今日の旅から考えたよ。次は秋の夕方、ここがきっと気に入るはず！」（話し方はアバターごと）。読み上げ「あり」なら「読み上げ」ボタン（開いただけでは読まない） | 話し方の辞書 |
| 3 | 予言カード（主色のカード） | `role="group"` と h2「次の旅の予言」。スポットのアイコン、スポット名（大）、いつ（「次の秋（9月〜11月）の夕方」。季節の月は `app/shared/dates.ts` の `seasonOf` と同じ）。h3「理由（大きい順）」と理由3つまで: 文・強さの文字（「強い」「中くらい」「弱い」）・強さの棒（飾り、`aria-hidden`）。カードを押すとスポット詳細（ボタン「このスポットを見る」） | API 14 `current`（`reasons`・`season`・`timeBand`） |
| 4 | 考え方 | 「あなたの旅と、みんなの旅（見本のデータ）から考えたよ。」と、開閉「どうやって考えたの？」（`<details>`、44px）: 点数の付け方と「外のサービスには送っていません」。「AI」と言い切らない | 固定の文 |
| 5 | 答え合わせのしかた | h2。「次に来た日（前回から7日以上あけた日）に、（スポット名）で QR を読むと答え合わせ。来てくれたら、さいころを2回」 | `current.spotId` |
| 6 | 相棒のかしこさ | h2。星5つ（★と☆、`aria-label`「かしこさ 5段階の2」）と「レベル2」、「これまでの予言: 2回中1回 当たり」 | `level`・`liked`・`normal` |
| 7 | 予言の記録 | h3。行ごとに「季節・スポット」と結果「○ 当たり」「△ ふつう」「― 答えていない」（記号と文字） | `history` |
| 8 | ほかの候補 | h2。2位・3位のスポット名と理由1つ。行を押すとスポット詳細 | `others` |
| 9 | Should の操作（作ったときだけ） | 「秋に知らせる（見本）」（R-029、頻度を選ぶ）、「ひらがなで見せる」（R-034）。**Must では出さない** | — |
| 10 | 下の操作 | 「（スポット名）を見る」（主ボタン）→ SC-04 | — |

### 表示B 答え合わせ
| # | 要素 | 内容・ルール | データ |
|---|------|--------------|--------|
| 1 | ヘッダー | 左に「もどる」、h1「予言の答え合わせ」、右に設定 | — |
| 2 | ごほうび（金の枠のカード） | h2「予言の場所に来てくれた！」、大きく「さいころ ＋2」、「答え合わせに来てくれたごほうびです。」（`role="status"`） | API 7 の `prophecyCheck` |
| 3 | 相棒の吹き出し | 相棒の `<img>`（alt「名前（わくわく）」）と「（スポット名）、どうだった？ 正直に教えてくれると、次の予言がもっと当たるよ」。**答え合わせは QR を読む操作のあとなので、読み上げ「あり」なら吹き出しと同時に読む** | 話し方の辞書 |
| 4 | 質問 | h2「（スポット名）は気に入った？」、「答えで、さいころの数は変わりません。」、3つのボタン（`role="group"`、各 58px）: 気に入った／ふつう／あとで答える | — |
| 5 | 結果（`role="status"`） | 気に入った:「○ 予言、当たり！」と、かしこさ・的中率の更新（例「相棒のかしこさが レベル3 になった（★★★☆☆）。これまで 3回中2回 当たり」）。ふつう:「△ ふつうだったね。次はもっと考えるよ」。あとで答える:「あとで答えられるよ（ホームの『次はどこ？』から）」 | API 15 |
| 6 | 下の操作 | 「すごろくで振る（あと n 回）」（主ボタン）→ SC-05 | `rollsLeft` |

- どちらの表示も下のメニューは出さない（サブ画面。方向性 §19.1）【仮定】。
- 予言と答え・ごほうびはサーバーが決めて記録する（画面から回数や結果を変えられない）。計算は ADR-010（外部 API・LLM を使わない）。

## 4. 状態
| 状態 | 画面 | 次の行動 |
|------|------|----------|
| 読み込み中 | カードの場所に灰色の枠と「（相棒）が考えています…」（`role="status"`） | 待つ |
| 空（まだ予言が無い。QR 0回） | 「スポットで QR を読むと、（相棒）が予言できるようになるよ」とボタン「スポットを探す」→ SC-03 | SC-03 |
| エラー | 「うまくいきませんでした。少し待ってから もう一度ためしてね。」と「もう一度」。答えの送信が 409（答え済み）なら最新の状態を取り直す | もう一度 |
| オフライン | 同じ PC のサーバーで計算するので、ネットが切れても見られ、答えも送れる。**地図が無いので「オフライン表示中」は出さない** | そのまま使う |
| 答えを待つ予言がある（表示A） | カードの上に「（スポット名）の答えを待っています」と表示B の質問だけを出す【仮定】 | 答える |
| 送信中 | 3つのボタンは押せない | 待つ |
| 旅の2日目に予言の場所で QR | 表示B は出さない。SC-04 の予言の場所のカードに「答え合わせは、次に来た日にできます」 | — |

## 8. アクセシビリティ（WCAG 2.2 AA）
| 達成基準 | 確認の観点 |
|----------|------------|
| 1.1.1 | 相棒の alt、スポットのアイコン・強さの棒は `aria-hidden`（強さは文字）。星は `aria-label` |
| 1.3.1 | h1 → h2 → h3。予言カードは `role="group"` と見出しで名前 |
| 1.4.1 | 当たり／ふつうを「○」「△」と文字で。強さは文字でも |
| 1.4.3 / 1.4.11 | 主色のカードの白文字と淡い金の文字（#FFF1D2／#0E7C74）を M4 で計算 |
| 2.2.1 | 答え合わせに時間の制限を設けない。「あとで答える」がある |
| 2.4.6 | 見出し「次の旅の予言」「答え合わせのしかた」「相棒のかしこさ」が内容を表す |
| 2.5.8 | 3つの答えのボタン 58px、開閉 44px |
| 3.2.2 | 答えを押しても画面は移らない（結果が出るだけ） |
| 4.1.3 | 答え合わせの結果・かしこさの上昇を `role="status"` で |

- 使いにくくなる人と対策（INC-01）: 文章が長いと読みにくい人→理由は3つまでの短い文。子ども→Should の「ひらがなで見せる」。
- だれのための工夫か（INC-03）: 「段差少なめ」の人に段差のある所を予言しないのは車いすの人（P-04）のためだが、高齢者（P-03）にも効く。

## 9. M4 の E2E で確かめる観点
- QR を1回以上読んだ後、ホームの「次はどこ？」から表示A が開き、スポット・理由（強さの文字つき）が出る。QR 0回なら「まだ」の案内（AC-038 の画面側）。
- 段差少なめを選ぶと段差のあるスポットが出ない（AC-039 の画面側）。
- デモで＋7日、予言のスポットで QR を読むと表示B、さいころ ＋2（AC-040 の画面側）。
- 「気に入った」で「○ 予言、当たり！」とかしこさ、もう一度押せない（AC-041・AC-042 の画面側）。

## 10. index.html との関係
- index.html に予言の画面は無い（方向性 §19.12）。見た目（主色 `#0E7C74`・金 `#F4B43A`・クリーム色の背景・カード角丸 24px・58px のボタン・48px のアイコンボタン）を index.html に合わせた。

## 11. 【仮定】
- 下のメニューを出さないサブ画面にする（SC-04 などと同じ）。
- 答えを待つ予言があるとき、表示A の上に質問だけを出す。
- 表示B の入口は SC-10（QR の後）。
