# SC-A15 お客さまの声（画面設計）

作成: 2026-11-09 17:20（実測） / 位置づけ: 追加企画（運営画面）。要件定義へは未反映 / モック: `docs/10_企画/画面モック/SC-A15_お客さまの声.html`（1対1。見た目の正は `admin.html#a15`）
上流: 運営向け画面_仕様案 §2（店舗は自店だけ）、§3（データの元 `notes`）、§5（画面一覧）、§5.1（画面の約束）、§7（US-113）、§8（API）。運営向け画面_1時間版 §3・§4.5。

## 1. 目的
店長の「**お客さまは何を感じて帰ったか**」に答える画面。自分の店で書かれた「ひとこと」を読み、**確認した印**を付ける。再訪の因果の「気持ち」の段を、数字ではなく声で見る場所。ほかの店の声は見えない。観光協会の画面には出さない（声そのものは店だけが読む）。

## 3. 要素（上から順）
| # | 要素 | 内容・ルール | データ |
|---|------|--------------|--------|
| 0 | 共通の枠 | 上の帯（役割のしるし「店舗: あかり堂」など・**期間の選択は使わない**【仮定】・「役割を変える」）、見本の注記、左のメニュー（店名の見出しの下に「店舗ダッシュボード」「お客さまの声」「近くの予定と特典マス」「自店のクーポン」。この画面に `aria-current="page"`）。SC-A01 の設計と同じ | — |
| 1 | 見出し | h1「お客さまの声（店名）」（モックの `SC-A15` の札は見本だけ） | 役割の店 |
| 2 | 説明 | 「あかり堂で書かれた『ひとこと』のうち、お店の人に見えると知らせたものだけを表示します。名前や ID は出ません。」（モックの「（見本の声。ダミーです）」は見本だけ。DEMO_MODE のダミーの声には「ダミー」の印を付ける【仮定】） | — |
| 3 | 数字のカード（3枚） | 「声の数」5件／「未確認」3件／「確認済み」2件。差は出さない | voices の件数 |
| 4 | 表示の選択 | ラベル「表示する声」・プルダウン（すべて／未確認だけ／確認済みだけ）。既定は「すべて」。選ぶと一覧が替わるだけで、別の画面へ移らない | 画面だけ |
| 5 | 声の一覧（`ul`） | 新しい順に最大50件【仮定】。1件ずつ: ①本文（太字。最大100字。React の通常の描画だけ。`innerHTML` を使わない）②日付（月/日）と年代（「11/08 ・ 20代」）③状態のチップ「未確認」「確認済み ✓」（文字と記号。色だけに頼らない）④未確認の声にだけボタン「確認した」（44px 以上） | `voices[]`（`id`・`text`・`day`・`age`・`confirmed`） |
| 5a | 伏せ字 | 本文の電話番号（数字6桁以上の並び）・メールアドレス・URL（`http`・`@` を含む語）は、サーバーが「（伏せました）」に置き替えてから返す。置き替えた声にはチップ「電話番号などを伏せました」を付ける【仮定】。元の本文は DB に残るが API では返さない | サーバーの規則 |
| 5b | 出さないもの | 書いた人の名前・ID・一緒に来た人・時刻・ほかの店の声。年代は5区分のまま。声が1件だけの日でも日付は日単位のまま（時刻は出さない）【仮定】 | — |
| 6 | 確認した | 押すと、その声は「確認済み ✓」に替わり、未確認の数が1減る。**自分の店の中だけの目印**で、書いた人には伝わらない。取り消しは作らない【仮定】。同じ声を2回押しても1回分 | `note_reads(note_id, shop_id)` |
| 7 | 注記 | 「声は、このお店で書かれた『ひとこと』だけです。電話番号・メール・URL は自動で伏せます。書いた人の名前・ID・一緒に来た人は出しません。ほかの店の声は見えません。『確認した』は、あなたの店の中だけの目印で、書いた人には伝わりません。」 | — |

- どの声を見せてよいか: 利用者アプリのひとこと画面で、「**お店の人に、名前を出さずに見えます**」と知らせたあとに書かれたものだけ（`notes.shop_visible = 1`）。それ以前に書かれたものは「ほかの人には見えません」と伝えて受け取ったので、**店には見せない**（この画面にも出さない）。
- 「このお店で書かれた」＝ `notes.spot_id` が役割の店（s8・s9・s11）のもの。観光スポット（s1〜s7・s10）で書かれたひとことは、この画面に出さない【仮定】。
- 応答に利用者の ID を含めない（R-057）。
- 店舗店長の画面にだけ出し、観光協会の画面には出さない（観光協会には件数も出さない【仮定】）。

## 4. 状態
| 状態 | 画面 | 次の行動 |
|------|------|----------|
| 読み込み中 | カードと一覧の場所に灰色の枠と「読み込み中…」（`aria-busy="true"`）。前の役割の声を出さない | 待つ |
| 空（声が0件） | カードは「0件」。一覧の場所に「まだお客さまの声はありません。お店の QR で『ひとこと』を書いてもらうと、ここに出ます。」【仮定】 | — |
| 空（選んだ表示で0件） | 「未確認の声はありません。」「確認済みの声はありません。」 | 表示を替える |
| エラー | 「声を読み込めませんでした。もう一度ためしてください。」と「もう一度」。ボタンの失敗は「確認の印を付けられませんでした」を `role="alert"` で出し、声は未確認のまま | もう一度 |
| 送信中 | 押した声のボタンだけ「確認しています…」で押せない（`aria-disabled`）。ほかの声は操作できる | 待つ |
| オフライン | 同じ PC のサーバーなので、ネットが切れても使える。表示は変えない | そのまま使う |
| 権限なし | `ADMIN_MODE` なしは 404。観光協会の役割・ほかの店の `:shopId` は 404（「この役割では使えない画面です」と「役割を変える」） | SC-A01 |

## 6. 使う API
| パス | いつ |
|------|------|
| GET `/api/admin/shops/:shopId/voices?show=all｜unread｜read` | 開いたとき・表示を替えたとき。`show` は許可リスト、query は1つずつ（配列は 400）。出力: `{ counts: { all, unread, read }, voices: { id, text, day, age, confirmed, masked }[] }`。`:shopId` は s8・s9・s11 の許可リストで、役割の店と同じときだけ（違えば 404）。`id` は声の連番で利用者を特定しない。`text` は 5a の伏せ字のあと |
| POST `/api/admin/shops/:shopId/voices/:noteId/confirm` | 「確認した」。本文 `{ requestId }`（`z.strictObject`）。`noteId` は整数。その店の声でなければ 404。2回目も成功（冪等） |

- 共通の決まり（Origin 検査・JSON だけ・`requestId`・`Cache-Control: no-store`・エラー形式）は `API設計.md` §1 と同じ。

## 7. 出典・オフラインの表示
- 運営画面は地図を出さない（仕様案 §5.1）。そのため「出典：地理院タイル」も「オフライン表示中」も出さない。
- サーバーは同じ PC（127.0.0.1）なので、ネットが切れてもこの画面は動く。

## 8. アクセシビリティ（WCAG 2.2 AA）
| 達成基準 | 確認の観点 |
|----------|------------|
| 1.3.1 | h1 → カード → フィルター → 一覧（`ul`・`li`）の順。一覧に `aria-label` |
| 1.4.1 | 未確認・確認済みは、チップの文字と ✓ の記号で示す（色だけにしない） |
| 1.4.3 | チップ（#3B2A00／#FFF1D2、緑／薄緑）と注記の小さい字のコントラストを M4 で計算 |
| 1.4.4・1.4.10 | 200% に拡大しても、声が1列に並び、横に流れない |
| 2.1.1・2.4.3 | Tab で表示の選択 → 各声の「確認した」の順に届く |
| 2.4.7・2.4.11 | フォーカスの枠が見え、上の帯（固定）に隠されない |
| 2.5.8 | 「確認した」・表示の選択は 44px 以上 |
| 3.3.2 | 「表示する声」のラベル。ボタンの名前は声ごとに違う（「11/08 20代の声を確認した」） |
| 4.1.2 | ボタンの名前・状態（送信中は `aria-disabled`）が読める |
| 4.1.3 | 確認したら「確認済みにしました（未確認 2件）」を `role="status"` で伝える。失敗は `role="alert"` |

- 使いにくくなる人と対策（INC-01）: 画面を見ながら接客する店長→1件ずつ短く区切り、確認はボタン1つ。
- だれのための工夫か（INC-03）: 状態を文字と記号で示すのは色覚に特徴がある店長のためだが、白黒で印刷して店で回し読みする場合にも効く。

## 9. 試験で確かめる観点（合否は書かない）
- 自店だけ: 他店の `:shopId`・観光協会の役割・`X-Operator` なしで 404／400。他店の声が応答に入らない。
- 見せてよい声だけ: `shop_visible = 0` のひとこと（案内を変える前に書かれたもの）が出ない。観光スポットで書かれたひとことが出ない。
- 個人情報: 応答に `guest-` の ID・名前・一緒に来た人・時刻が含まれない。電話番号・メール・URL が「（伏せました）」になる。
- 確認: 「確認した」で未確認が1減り、2回押しても1回分。ほかの店の確認の印に影響しない。
- 表示: `show` が許可リスト外・配列は 400。本文に `<script>` があっても文字として表示される（`innerHTML` を使わない）。
- アクセシビリティ: キーボードだけで確認できる、状態が文字と記号で分かる、200% 拡大で横に流れない。

## 10. 【仮定】
- 店に見せてよいのは、案内を変えたあとに書かれた、自店で書かれたひとこと（`notes.shop_visible`）だけ。利用者アプリのひとこと画面の案内を「名前や連絡先は書かないでね。お店の人には、名前を出さずに見えます。」に変える（`words-spots.ts` の `notePriv`。共通ファイルなので本体が直す）。
- 伏せ字の規則（数字6桁以上・メール・URL）と、「確認した」の取り消しなし、新しい順に最大50件。
- 声を店だけに出し、観光協会には出さない。
- 年代と日付だけを出す。一緒に来た人・時刻は出さない。
- DEMO_MODE では、自店の見本の声（ダミー）を数件入れる。
