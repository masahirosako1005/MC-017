# ADR-008 アプリ内の今日（JST）と DEMO_MODE
- 状態: 採用
- 日付: 2026-11-09
- 対応: R-005 / R-043 / R-044 / R-045 / R-046 / AC-051〜AC-055 / U-01 / U-07
## 背景
再訪（7日以上あけて開く）や答え合わせは、実際に7日待たないと見せられない。ユーザー指示（14:00）: 位置と日時を切り替えるデモは DEMO_MODE の時だけ入れる。端末の時計は変えない（方向性 §4）。
## 決定
1. サーバーの時計 `services/clock.ts` が「アプリ内の今」を返す: 実際の今（JST、UTC+9 固定）＋ 利用者の `demo_offset_days` 日、時刻は `demo_hour` があればその時。**DEMO_MODE でないときは、ずれを読まない**（0日・実時刻）。
2. 環境変数 `DEMO_MODE=1` のときだけ、`/api/demo/clock`・`/api/demo/location`・`/api/demo/rolls` の route を登録し、`/api/config` が `demoMode: true` を返し、`MeState.demo` に値を入れる。画面は `demoMode` が真のときだけ設定にデモ操作を出す。
3. 位置のデモは「いる場所」をスポットから選ぶだけ。実際の位置情報は使わない（Permissions-Policy で `geolocation=()`）。
4. デモの回数の付与は `grants.source='demo'` で記録し、ふつうの付与と分ける。
## 理由
route を登録しないので、DEMO_MODE なしではデモの操作が存在しない（ふつうの 404 と同じ）。時計を1か所にまとめると、再訪の判定・うわさ・クーポンの日付がすべてそれに従う。
## 検討した代替案（採らなかった理由）
- 画面で日付をずらして送る: サーバーの判定を画面が決めることになり、改ざんできる。
- サーバー全体の時計を変える: 利用者ごとに試せず、E2E の状態が混ざる。
## 結果・影響（良い点・悪い点・注意）
良い点: デモが数分で通る。DEMO_MODE なしでは何も出ない（AC-051・AC-052）。悪い点: 戻す（過去へ）操作は作らない（ずれは 0〜3650 日）。注意: `npm start` の既定は DEMO_MODE なし。デモの起動は README に書く。
## 【仮定】（資料にない前提。無ければ「なし」）
ずれは日単位と時刻だけ。位置は「スポットにいる」形だけ。
