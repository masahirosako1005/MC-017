# ADR-015 E2E の状態の戻し方とサーバーの分け方
- 状態: 採用
- 日付: 2026-11-09
- 対応: R-051 / R-045 / AC-014 / AC-051〜AC-052 / AC-056 / U-08
## 背景
environment ルール: E2E は1並列、dev を止め、`reuseExistingServer: false`、DB は `:memory:`、毎回状態を初期に戻す、順序依存を作らない。試験には DEMO_MODE なし（AC-052）とオフラインの再現も要る。地理院のタイルは外部の通信。
## 決定
1. Playwright の `webServer` を2つ: 3000 は `DEMO_MODE=1`・`DB_PATH=:memory:`、3100 は DEMO_MODE なし・`:memory:`（DEMO_MODE なしの試験だけ使う）。どちらも本番ビルドを tsx で配る。
2. 状態の戻し方: 各試験は新しいブラウザのコンテキスト（localStorage が空）で始まり、新しいダミー ID を作る。サーバーの状態は利用者ごとなので、別の ID なら混ざらない。CSV 由来の表は起動時に1回だけ入る（読み取り専用の扱い）。DB を消すための API は作らない。
3. 外部の通信: すべての試験で `context.route` を使い、`cyberjapandata.gsi.go.jp` のタイルは 1×1 の PNG を返す（オフラインの試験は abort）。それ以外の外部の要求は abort して記録し、0件であることを確かめる（AC-056）。
4. 読み上げは `/api/tts` を route で差し替える（無音の短い WAV か 503）。
5. 実行後、Playwright がサーバーを止める。手で 3000・3100・5173 が空いていることを確かめて試験結果に書く。
## 理由
DB を消す API はデモ以外の攻撃面になる。利用者ごとに分ける設計なので、ID を新しくすれば状態は初期と同じ。タイルを差し替えると、ネットの有無で結果が変わらない。
## 検討した代替案（採らなかった理由）
- 試験ごとにサーバーを再起動: 遅い（試験数×起動時間）。
- リセット用の API（DEMO_MODE のみ）: 便利だが、状態を消す操作が増える。
## 結果・影響（良い点・悪い点・注意）
良い点: 順序に依存しない。悪い点: CSV 由来の集計（うわさ）は全試験で同じ。注意: 3100 は環境ルールの【仮定】のポート（3000・5173）に足す E2E 専用のポート【仮定】。
## 【仮定】（資料にない前提。無ければ「なし」）
3100 番。DB を消す API を作らないこと。
