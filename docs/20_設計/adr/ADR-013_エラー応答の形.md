# ADR-013 エラー応答の形と 404 の自前ハンドラ
- 状態: 採用
- 日付: 2026-11-09
- 対応: R-050 / R-055 / AC-059 / U-01
## 背景
security-quality ルール: 404 とエラーも自前で返し、同じヘッダを付け、`Cannot GET` を出さない。スタック・内部パス・SQL・版を含めない。
## 決定
1. API の誤りはすべて `{"error":{"code":"…","message":"…"}}`（code は API 設計 §1 の8種、message は短い英語）。画面は code から辞書の日本語／英語の文言を出す。
2. `/api/*` に合う route が無ければ 404 `not_found`。それ以外のパスは、本番配信では `index.html`（SPA）を返し、`/assets/` の無いファイルは 404 の JSON。
3. 最後のエラーハンドラ（引数4つ）は、JSON の構文誤り 400、大きすぎ 413、それ以外 500 `internal`。詳細（名前・メッセージ）はサーバーのログだけで、改行をエスケープして1行に。
4. `process.on('uncaughtException')` はログして終了する。
## 理由
形を1つにすると、画面の扱いと試験（AC-059）がそろう。英語の短い message は開発者向けで、利用者向けの文言は辞書に置く（i18n）。
## 検討した代替案（採らなかった理由）
- RFC 9457（problem+json）: 項目が多く、今回は code と message で足りる。
- 日本語の message をサーバーで返す: 英語表示（R-034 系）とずれる。
## 結果・影響（良い点・悪い点・注意）
良い点: 漏れが無い。悪い点: 画面の辞書に code ごとの文言が要る。注意: Express 5 の `express.json()` のエラー（`type: 'entity.parse.failed'` 等）を見分ける。
## 【仮定】（資料にない前提。無ければ「なし」）
code の名前の付け方。
