# ADR-019 推移依存も許可リストで固める（vite 7・React プラグインなし・ESLint なし）
- 状態: 採用（ADR-017 を置き換える）
- 日付: 2026-11-09
- 対応: R-055 / QL-LINT-01 / U-01
## 背景
2026-11-09 14:21 に導入して `node_modules` を走査すると、直接入れたものはすべて許可リスト内だったが、推移依存に許可外が見つかった: lightningcss（MPL-2.0、vite 8 の必須の依存）、minimatch 10.2.6（BlueOak-1.0.0、eslint 10 と typescript-eslint 8 の依存）、caniuse-lite（CC-BY-4.0、@vitejs/plugin-react 5 → @babel/core の依存）。competition ルールの許可は MIT / BSD / Apache / ISC のみ。
## 決定
1. vite は 7 系（7.3.7）。lightningcss は任意の peer なので入らない。
2. @vitejs/plugin-react は入れない。TSX は Vite 内蔵の esbuild で変換する（`esbuild: { jsx: 'automatic' }`）。
3. ESLint と typescript-eslint は入れない。代わりに `scripts/check-forbidden.ts`（依存なし）で、`innerHTML`・`outerHTML`・`insertAdjacentHTML`・`dangerouslySetInnerHTML`・`document.write`・`eval(`・`new Function`・明示の `any`・理由のない `@ts-ignore`／`@ts-expect-error`・SQL の文字列連結（`prepare(` の引数にテンプレートの `${`）・`res.redirect`・`0.0.0.0` を探し、見つかれば終了コード 1。`npm run lint` はこのスクリプトを実行する。
4. 依存を足すたびに推移依存まで走査する（外部リソース.md §2 の走査のコマンド）。
## 理由
許可リストは制約で、評価（lint の網羅性）より優先する（competition ルール「制約を優先」）。型の誤りは `tsc` の strict と ADR-016 の厳格化で多くを止められ、ESLint の主な目的（禁止事項）は正規表現で足りる。
## 検討した代替案（採らなかった理由）
- `overrides` で minimatch を 9 系（ISC）に固定: eslint 10 が 10 系の API を前提にしている恐れがあり、動作の確認に時間がかかる。
- vite 8 のまま: MPL-2.0 が必ず入る。
- Biome（MIT/Apache）: 新しい依存の確認が要り、ネイティブのバイナリも入る。
## 結果・影響（良い点・悪い点・注意）
良い点: 依存が 126 件まで減り、すべて許可内、`npm audit` 0 件。悪い点: React の開発時の Fast Refresh が無い（再読み込みで足りる）。lint は正規表現なので、文字列の中やコメントの誤検出があり得る（除外の書き方をスクリプトに書く）。注意: vite 7 は Node 20.19+ / 22.12+ が必要（環境は 24.21.0）。
## 【仮定】（資料にない前提。無ければ「なし」）
「許可リスト」が推移依存にも及ぶと解釈すること（外部リソース.md §1・`/check` B-11 の扱いに合わせた）。
