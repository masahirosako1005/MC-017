# ADR-007 さいころの目と回数はサーバーで決める
- 状態: 採用
- 日付: 2026-11-09
- 対応: R-017 / R-019 / R-020 / R-056 / U-01 / U-03
## 背景
方向性 §7・§16.3: 目と回数の上限はサーバーで決めて記録し、画面の操作だけで増やせないようにする。
## 決定
`POST /api/rolls` の1トランザクションで、残り回数（付与の合計 − 振った数）が1以上かを確かめ、`crypto.randomInt(1, 7)` で目を決め、盤の位置を進め（49 で止める）、`rolls` に記録し、🎁ならクーポン、ゴールなら次の盤とゴール特典を作る。画面はサーバーの目で止まるように転がしを見せるだけ。盤の進み方とマスの判定は `app/shared/board.ts` の純粋関数にして試験する。
## 理由
画面の値を信じないので、回数・目・クーポンを改ざんできない（データ完全性）。純粋関数にすると目を決め打ちして試験できる。
## 検討した代替案（採らなかった理由）
- 画面で目を決めて送る: 好きな目を送れる。
- 決まった乱数の種: 予測できてしまう。試験は純粋関数で目を与えて行う。
## 結果・影響（良い点・悪い点・注意）
良い点: 試験しやすく、改ざんに強い。悪い点: オフライン（サーバーに届かない）では振れない（「つながりませんでした」と出す）。注意: 演出の約3秒は画面側だけで、サーバーはすぐ返す。
## 【仮定】（資料にない前提。無ければ「なし」）
ゴールはちょうどでなくてよい（越える目でもゴールで止まる。方向性 §16.3）。
