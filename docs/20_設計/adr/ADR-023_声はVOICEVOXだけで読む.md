# ADR-023 声は VOICEVOX だけで読み、止まっていてもブラウザの声へは自動で切り替えない
- 状態: 採用（ADR-011 の3・5 を置き換える）
- 日付: 2026-11-09（2026-11-09 17:25 実測）
- 対応: R-037・R-041 / AC-045・AC-048 / SC-12・SC-01・SC-05（読み上げ）/ U-01・U-07
## 背景
人の指示「音声は VOICEVOX を使うように変更して」。ADR-011 では「自動（VOICEVOX 優先）」とし、VOICEVOX が止まっていると黙ってブラウザの端末内の声（Nanami など）へ切り替えていた。エンジンは別に起動する必要があり、起動していないと利用者が聞くのはいつもブラウザの声になり、VOICEVOX を使っていることにならなかった。この PC では VOICEVOX ENGINE 0.26.1 が C:\voicevox-work\windows-cpu\ に導入済み（音声合成の準備.md）。
## 決定
1. 設定の「声」の既定を **VOICEVOX** とし、VOICEVOX だけで読む。止まっていても、ブラウザの声へは**自動で切り替えない**。読まずに文字だけにして、吹き出しの「読み上げ」を押したときは「VOICEVOX が起動していないので、声は出せません（文字は読めます）」を出す。設定の「いまの声」には「VOICEVOX が起動していません（文字だけ）」と出す。
2. 「ブラウザの声」は**利用者が設定で選んだときだけ**使う（R-041 の「代わりの読み上げ」は残す。選び方・T-049 は変えない）。
3. English にしても VOICEVOX で読む【仮定】（以前は English だけブラウザの声）。話者は日本語向けのため、英語の文は聞き取りにくいことがある。
4. エンジンを起動する 
pm run start:voice（scripts/start-voicevox.ps1。127.0.0.1:50021 だけ、--disable_mutable_api）を足し、README に書く。アプリのサーバーは今までどおり、エンジンが止まっていても動き続け、30秒に1回確かめ直す（R-040）。
## 理由
1. 指示は「VOICEVOX を使う」。黙って別の声に替わると、使っていないことに気づけない。
2. 声が出ない理由を見せれば、利用者は「
pm run start:voice で起動する」か「ブラウザの声に替える」かを選べる。
3. 競技の制約（外部へ送らない・オフライン）は変わらない: エンジンは同じ PC の 127.0.0.1 だけ。エンジンが無くても全機能は文字で動く。
## 検討した代替案（採らなかった理由）
- ブラウザの声の選択肢ごと消す: R-041（Must）を削ることになり、止まる条件に当たる。残した。
- アプリのサーバーがエンジンを子プロセスとして起動する: child_process は禁止（ADR-020 の lint）。別のスクリプトにした。
- English はブラウザの声のまま: 「音声は VOICEVOX」に反する。English の聞き取りにくさは【仮定】として残す。
## 結果・影響（良い点・悪い点・注意）
良い点: 聞こえる声が常に VOICEVOX の話者（クレジット表示あり）になる。悪い点: エンジンを起動していない環境では、既定では声が出ない（文字だけ）。デモの前に 
pm run start:voice を別のターミナルで動かし、応答まで約50秒待つ。注意: 試験は /api/tts を取り替えて行うため、エンジンの有無に左右されない。
## 【仮定】（資料にない前提。無ければ「なし」）
- English でも VOICEVOX で読む。
- エンジンの場所の既定は C:\voicevox-work\windows-cpu（環境変数 VOICEVOX_DIR で変更）。
