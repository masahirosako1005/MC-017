# ADR-021 スポット一覧を削除し、ドラッグの代わりをアイコンのキーボード操作にする
- 状態: 採用
- 日付: 2026-11-09（16:59 実測）
- 対応: R-011（Must → 削除）/ US-011 / AC-015 / T-015 / R-008 / WCAG 2.5.7・1.4.10 / SC-03 / U-02
## 背景
SC-03 には、地図と同じスポットを行で並べる「一覧で見る」があった（R-011、Must）。ドラッグなしで全スポットへ行く手段（WCAG 2.5.7）と、地図が苦手な人の代わりを兼ねていた。利用者が 2026-11-09 16:47 に「『一覧を見る』を削除して」と指示した。一覧の入口はこのボタンだけで、消すと一覧は使えなくなり、Must を削ることになる。そのため AskQuestion で3択（ボタンだけ消して一覧は地図の下に並べる／ボタンも一覧も消す／残す）を示し、利用者が「ボタンも一覧も消す」を選んだ（`人の判断`）。
## 決定
1. SC-03 から「一覧で見る」ボタンと一覧の表示（`SpotList`・`listOrder`・`mode`）を削除する。R-011 と AC-015 は「削除」とし、T-015 は削除の確認の試験に差し替える。
2. 代わりのドラッグなしの手段は、アイコンへの Tab と Enter／Space（概要が開く）、Esc、拡大・縮小ボタンとする。Leaflet 1.9.4 はポップアップが無いと Enter で click を出さないので、アイコンに `keydown` を自前で付ける。
3. デモの「いる場所」の近い順の一覧（AC-054 の後半）も無くなる。「いまここ（デモ）」は地図に出す。
## 理由
- 利用者の明示の指示で、選択肢を示したうえで決めた。
- アイコンは11個で、すべてに「名前、季節」の名前と Tab の順序がある。ドラッグが必須の操作は無い。
## 検討した代替案（採らなかった理由）
- 一覧を地図の下に常に並べる: Must を保ちアクセシビリティを守れるが、利用者は一覧そのものを消す方を選んだ。
- 変更しない: 利用者の指示に反する。
## 結果・影響（良い点・悪い点・注意）
- 良い点: 画面が地図中心になり、季節タブの下がすぐ地図。コードが減った（辞書3語・CSS・`SpotList`）。
- 悪い点: 地図が見づらい人・スクリーンリーダーの人が全スポットを一度に見る手段が無い。WCAG 1.4.10 の「二次元の内容の代わり」は M5 で確認する（未確認が残る）。Must が1つ減った。
- 注意: アイコンの Enter／Space は以前から無く（WCAG 2.1.1 の抜け）、この変更の中で直した（`AIの誤り`）。E2E は一覧の代わりに共通の `openSpotDetail`（要素の click）で詳細へ入る。
## 【仮定】
- 簡易地図（オフライン）でも同じ部品なので Enter／Space が使える。
- 地図の矢印キー操作は Leaflet 標準のまま。
