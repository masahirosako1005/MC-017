# ADR-022 すごろくの盤を45マス（左上スタート・右下ゴール）にし、さいころを画面いっぱいで約4.8秒転がす
- 状態: 採用
- 日付: 2026-11-09（17:04 実測）
- 対応: R-018・R-023 / AC-025・AC-030・AC-067・AC-068 / SC-05 / U-03
## 背景
人の指示「これをアプリに取り込んで」（2026-11-09。直前の指示で作ったモック `SC-05_すごろく_新盤面案.html`、可愛い盤・ジグザグ・スタートが左上でゴールが右下・ゴールに名古屋城・特典マスは約1/5・さいころは盤の上に画面いっぱいで、コロコロ転がってゆっくり止まる）を、アプリに取り込む。それまでの設計は「50マス・1段5マス・10段、下がスタート・上がゴール、さいころは約3秒で状況のカードの中」（R-018・R-023）で、決めた理由は ADR-002・方向性 §16 にあった。
## 決定
1. 盤は **1段5マス×9段＝45マス**（`COLS=5`、`ROWS=9`、`BOARD_SIZE=45`、`GOAL=44`）。1段目は左→右、2段目は右→左…とジグザグにし、**スタートは左上、ゴールは右下**。段数を奇数にするのは、偶数だとゴールが左下になるため。
2. 1枚目の🎁マスは 4・8・13・17・22・26・31・36・42 の**9マス（45の1/5）**。スポットは 2・11・20・29・38。2枚目は🎁15・スポット2・季節5（1/5ではなく、R-020 の密度のまま）を45マスに並べ直す【仮定】。
3. 盤は SVG（viewBox 360×1190）に、背景・道・マス・名古屋城（ゴールのまわり）を描き、画面の幅に合わせて拡大縮小する。駒は HTML の `div.piece`（既存の `Avatar`）を % で重ねる。
4. さいころは `role="dialog"` `aria-modal="true"` の**全画面の重ね表示**（`DiceOverlay`）。Web Animations API（外部の CSS ファイルから付けるクラスと、`element.animate`）で、約4.8秒かけて転がし、止まったら約1.2秒見せて閉じる。「とばす」・Escape で切り上げる。動きを減らす設定では回さず約0.5秒で面を出し約0.7秒で閉じる。目はこれまでどおりサーバーが決める（ADR-007）。
5. DB の `users.pos`・`rolls.from_pos/to_pos` の CHECK を 0〜44、`coupons.square` を 1〜44 にする。50マスだった頃のファイルDBに残った位置（45以上）は、`openDb` の最後の `normalizeBoardPositions` でゴールの1つ手前（43）へ戻す。
## 理由
1. 指示の「スタートが左上・ゴールが右下」を満たすには段数が奇数でなければならず、1段5マスなら45か55。50に近く、特典を1/5にできて（45÷5＝9）、スマホで見て長すぎない45にした。
2. 盤を SVG の1枚にすると、絵（名古屋城・背景）とマスの位置が同じ座標で決まり、幅が変わってもずれない。マスに `data-sq` を持たせ、E2E がマスの位置を測れる。
3. さいころの全画面は「止まるまで目が離せない」演出で、約4.8秒の転がりは WCAG 2.2.2（5秒を超える動きは止められること）を「とばす」・Escape で満たす。サーバーが目を決めるので、サーバーの応答が遅くても「ゆっくり回して待つ」状態を挟めば演出は成り立つ。
4. ファイルDBが残る端末でも盤の外に出ないよう、起動時に補正する（CHECK を狭めただけでは、既存の行が更新のたびに失敗する）。
## 検討した代替案（採らなかった理由）
- 50マスのまま向きだけ変える: 10段だとゴールが左下になる。指示（右下）に反する。
- 55マス: 1/5＝11マスにできるが、盤が縦に長くなり、1回で遠くへ進んだ感じが減る。
- 背後に `inert` を付ける: React 19 の描画との相性の確認に時間がかかる。`aria-modal` と Tab の閉じ込めで足りる。
- 約1.7秒で自動で閉じる（モックの値）: 目を見せる時間が短く、結果を読む前に盤へ戻る。約1.2秒に伸ばし、「すすむ」で先へ進めるようにした。
- 2枚目も🎁を1/5（9マス）にする: R-020 の「2枚目は🎁が多い」が弱まる。今回は既存のまま【仮定】。
- 既存のファイルDBを作り直す: 旅の続き（R-021）を壊す。位置だけを補正する。
## 結果・影響（良い点・悪い点・注意）
良い点: 指示どおりの盤・演出になり、E2E でマスの位置（左上スタート・右下ゴール）と全画面（スマホの枠いっぱい）を測れる。悪い点: 1回振ってから駒が動くまで約7秒かかる（転がり 4.8＋見せる 1.2＋間 0.25＋跳ねる 0.26×歩数）。E2E の待ち時間を伸ばした（10→20秒）。注意: `board.ts` のマス数を変えるときは、DB の CHECK（`db/schema.sql`）、`normalizeBoardPositions`、試験（T-025・T-067）、データ設計 §2.2 を一緒に直す。
## 【仮定】（資料にない前提。無ければ「なし」）
- 2枚目の🎁15・スポット2・季節5を45マスへ並べ直した位置（資料なし）。
- 1枚目の最後の🎁をモックの40から42に変えた（ゴールの手前3マス以内に🎁を置き、「ゴール優先」の案内を試験するため）。
- 転がり約4.8秒・見せる約1.2秒（動きを減らす設定は約0.5秒・約0.7秒）。
- スポット名・特典名はモックの見本ではなく、実データ（既存のマスタ）を使う。
