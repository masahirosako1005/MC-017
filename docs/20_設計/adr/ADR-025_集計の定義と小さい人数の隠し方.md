# ADR-025 集計の定義と小さい人数の隠し方
- 状態: 採用
- 日付: 2026-11-10
- 対応: R-072 / R-073 / R-076 / U-09 / U-12
## 背景
運営向けの数字から、個人（誰がいつ何をしたか）が分かってはいけない。人数が少ないと、数字だけで個人が分かる。
## 決定
1. **5人未満は数字を出さない**（値は `null`・`hidden`、画面は「5人未満」）。0 はそのまま出す。割合は**母数が5未満**なら隠し、**30未満**なら「参考」を付ける。合計は、内訳に隠した行があるとき「n人以上」（内訳の合計から隠した人数を引き算で当てられない）。「あと何人」は5人以上のときだけ出す。閾値（10人）は定数。
2. 応答に利用者 ID（`guest-…`）を含めない。ID は repository の外へ出さない約束で、service は人数だけを返す。
3. 指標の数え方: K-01 は期間に `visits` がある人、K-02 は `visits.kind='revisit'`（旅の2日目は数えない）がある人 ÷ K-01、**K-03 は来た日の終わりに「盤の途中（1〜43マス。ゴールに着いた直後は0に戻るので数えない）・開いた予定・翌日以降に使える券」のどれかを持つ割合**、K-07 は `season`・`goal`・`campaign` の券の使われた割合。再訪までの段階は、各段階が前の段階を通った人だけ。**期間の終わりは記録のある最後の日**（デモの日付送りでも見える）、前の期間は同じ長さの1つ前。
4. 気づき（d）は K-03 が前の期間より5ポイント以上下がったときの1件だけ（どちらも隠れていないとき）。
5. お客さまの声は、サーバーで電話番号（数字6つ以上。全角は半角に直して探す）・メール・URL を「（伏せました）」に置き替えてから返す。年代・日付・本文だけを返し、名前・ID・一緒に来た人・時刻は返さない。
## 理由
少人数の数字は個人を特定できる。引き算で当てられる合計・差を避けるため、合計と内訳の見せ方をそろえる。
## 検討した代替案（採らなかった理由）
- 小さい数に乱数のノイズを足す: 再現できず、試験が書けない。
- 一律に10人未満を隠す: 閾値と同じで厳しすぎ、店の小さい数字が全部消える。
## 結果・影響（良い点・悪い点・注意）
良い点: 個人が出ない・試験で手計算と比べられる。悪い点: 小さい数は見えない。注意: 伏せ字は完全ではない（`零九零…` のような書き方は残る）。見せる前にお客さまへ「お店の人に見える」と知らせている（ひとこと画面の案内）ので、書く側の注意と組み合わせる。
## 【仮定】（資料にない前提。無ければ「なし」）
5人・30人・10人の閾値、K-03 の「理由」の定義、期間の終わり＝記録のある最後の日。

## 変更（2026-11-10 12:19、人の判断）
- 指示「5人未満でも数字を表示するようにして」により、pp/shared/master/campaigns.ts の HIDE_BELOW を 5 から **1** にした＝1人以上は数字をそのまま出す（0 人の割合だけ「データがありません」）。割合の「参考」（母数 30 未満）は残す。需要の『あと n 人』も出る。戻すときは定数を 5 に戻す（試験は 5 人未満の隠れ方を確かめていないので、戻すなら試験も戻す）。
- 理由と注意: ダミーの利用者と個人を特定しない集計なので、1人の数字が出ても名前・ID は出ない。実運用では少人数の数字から個人が推測される恐れがあるため【仮定】で見直す。
