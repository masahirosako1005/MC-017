# ADR-009 CSV 取込（自前の読み取り・起動時に冪等）
- 状態: 採用
- 日付: 2026-11-09
- 対応: R-028 / R-027 / R-030 / R-057 / AC-035〜AC-037 / U-01
## 背景
CSV 5本は UTF-8・BOM あり・CRLF・引用符なし（データ調査 §1.1）。competition ルール: 読み取り専用・複写しない・`SAMPLE_DATA_DIR`。csv-parse（MIT）は「必要性を設計で確認してから」の候補だった。
## 決定
1. `app/server/src/import/csv.ts` に自前の読み取りを書く（BOM 除去、CRLF/LF、引用符と `""`、不正な UTF-8 で止める）。csv-parse は入れない。
2. 使う列だけを取り出してから zod で検証する（データ設計 §4.2）。個人に見える列は取り出さない。
3. 起動時（listen 前）に 13 → 12 → 18 の順で、1ファイル1トランザクションの `INSERT OR IGNORE`。件数（行・取込・除外と理由）を `import_log` とログに出す。`npm run import:csv` でも同じ処理を実行できる。
4. CSV の7スポットは名古屋のスポットへ対応表で割り当てる（データ設計 §2.1）。一緒に来た人はユーザー ID mod 4 で付ける。
## 理由
引用符なしの小さな CSV で、規格上の引用符にも対応する読み取りは短く書ける。依存を増やさない（competition ルール「標準機能で足りるなら入れない」）。一意キーで冪等にすると、何度起動しても件数が増えない。
## 検討した代替案（採らなかった理由）
- csv-parse: 依存が増える。今回の CSV には要らない機能が多い。
- 起動のたびに表を消して入れ直す: 途中で失敗すると空になる。
## 結果・影響（良い点・悪い点・注意）
良い点: 依存なし・冪等・試験しやすい。悪い点: 読み取りの試験を自分で書く（引用符・BOM・不正な行）。注意: 13 の特典獲得数の不一致（227人）はログに出すだけで直さない（データ調査 §3-3）。
## 【仮定】（資料にない前提。無ければ「なし」）
08・09 を取り込まない。スポットの対応表と一緒に来た人の付け方。
