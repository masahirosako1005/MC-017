# ADR-020 任意の追加策（Trusted Types・Node の Permission Model・セキュリティ用 lint）の採否
- 状態: 採用
- 日付: 2026-11-09（15:33 実測）
- 対応: R-061（Could）/ SEC-XSS-12・SEC-NODE-08・SEC-NODE-10 / U-01・U-08
## 背景
セキュリティ品質チェックリストは、資料が「任意」とする3つの追加策について、採否と理由を ADR に書くよう求めている（M3）。要件定義では Trusted Types を Could（R-061）とし、非機能・セキュリティ設計 §7 に「Could」とだけ書いていた。M3 ゲートで ADR が無いことが分かったため、本 ADR にまとめる。
## 決定
1. **Trusted Types**（`require-trusted-types-for 'script'`）は今回は付けない（R-061 は Could のまま）。
2. **Node の Permission Model**（`--permission`）は使わない。
3. **セキュリティ用 lint**（`eslint-plugin-security`）は入れない。代わりに `scripts/check-forbidden.ts`（`npm run lint`）で禁止事項（`innerHTML` 等・`eval`・`child_process`・SQL の文字列連結・`res.redirect`・`any` ほか）を検査し、TypeScript の `strict` と追加の厳格化（ADR-016）を全 tsconfig に付ける。
## 理由
1. 文字列から DOM を作る経路が無い（`innerHTML` 等は lint で0件、React の通常描画と `textContent`、Leaflet のマーカーは DOM 要素を渡す ADR-012）。Trusted Types を付けると、Leaflet と React の内部が型付きの値を求められる箇所の確認が要り、3.5h の製造に収まらない。
2. `better-sqlite3` はネイティブアドオンのため `--allow-addons` が要り、ファイルの読み取り許可（CSV・dist）も細かく指定する必要がある。サーバーは 127.0.0.1 のみ listen・外部へ送らない・子プロセスを使わないため、得られる効果に比べて設定の誤りで動かなくなる危険が大きい。
3. ESLint は推移依存（minimatch 10、BlueOak-1.0.0）が許可ライセンス外のため入れられない（ADR-017・ADR-019）。`eslint-plugin-security` も ESLint が前提。
## 検討した代替案（採らなかった理由）
- Trusted Types を report-only で出す: 違反の報告先（`report-to`）が外部になるか、自前の受け口を作る必要がある。今回は作らない。
- Permission Model を `--allow-fs-read` 付きで使う: 上の理由2。
- ESLint 以外のセキュリティ lint: 許可ライセンスで ESLint に依らないものを確認できていない【仮定】。
## 結果・影響（良い点・悪い点・注意）
良い点: 依存と設定が増えない。悪い点: 将来 `innerHTML` 相当の経路が入ったとき、ブラウザ側で止める仕組みが無い。注意: `npm run lint` の禁止事項の検査を外さない。M5 で V2（禁止パターン）を実行して0件を確かめる。
## 【仮定】（資料にない前提。無ければ「なし」）
ESLint に依らない許可ライセンスのセキュリティ lint は無いものとした（未調査）。
