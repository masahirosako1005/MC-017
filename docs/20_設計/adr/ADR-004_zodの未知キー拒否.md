# ADR-004 zod の未知キー拒否は z.strictObject
- 状態: 採用
- 日付: 2026-11-09
- 対応: R-052 / R-040 / U-01
## 背景
security-quality ルールは「未知キーの拒否方法（`.strict()` か `z.strictObject`）は M3 で zod 公式を読んで決め、ADR に書く」とした。2026-11-09 14:12 に zod.dev の API ページ（Objects 節）を読んだ: `z.object()` は既定で未知キーを取り除く、`z.strictObject` は未知キーがあるとエラー、`z.looseObject` は通す。`.strict()` も同じ節の例に出てくる。
## 決定
API の body・query・params と CSV の行・環境変数の検証は、すべて `z.strictObject` で書く（CSV の行は列名を検証した後に使う列だけを取り出してから検証する）。`z.object` と `.strict()` は使わない。
## 理由
公式ページの書き方で、未知キーを黙って捨てずに 400 にできる（SEC-IN-03）。関数の形に統一すると、書き忘れを `Select-String 'z\.object\('` で見つけられる。
## 検討した代替案（採らなかった理由）
- `z.object().strict()`: 動くが、付け忘れが見つけにくい。
- `z.object()`（取り除く）: 誤った入力を黙って受け入れ、利用者が気づけない。
## 結果・影響（良い点・悪い点・注意）
良い点: 余計なキーで状態が変わらない。悪い点: クライアントがキーを足すとすぐ 400 になる（同じ `app/shared/schemas.ts` を使うので起きにくい）。注意: CSV の行は列が多いので、行のオブジェクトをそのまま strict にしない。
## 【仮定】（資料にない前提。無ければ「なし」）
なし
