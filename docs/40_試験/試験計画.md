# 試験計画

- 作成: 2026-11-09 16:10（`Get-Date` で実測）
- 上流: `docs/10_企画/要件定義.md`（R-001〜R-057・AC-001〜AC-066）、`docs/20_設計/ユニット計画.md`（U-01〜U-08）、ADR-015（E2E の進め方）
- 試験項目: `試験項目.md`（T-001〜T-066、AC と1対1）。結果: `試験結果.md`。通しの手順: `E2Eデモシナリオ.md`

## 1. 目的
受け入れ基準をすべて自動の試験で確かめ、競技の制約（外へ出ない・HSTS なし・個人情報なし・元 CSV を変えない）が守られていることを、毎回同じ手順で示す。

## 2. 範囲
| 対象 | やり方 |
|---|---|
| サーバー（route → service → repository、取込、ヘッダ、入力検証、データ完全性） | Vitest（U）。サーバーを `127.0.0.1` のランダムなポートで起動し、`fetch` で呼ぶ。DB は `:memory:` |
| 画面（表示・操作・アクセシビリティの自動で分かる所） | Playwright（E）。Edge（`channel: msedge`、端末に入っているもの） |
| 手でしか確かめられない所 | §5 の手順（M5） |
| 対象外 | 運用（Phase 4、localhost のみ）。負荷試験。実機のスマホ（390/430px の画面幅で代える）【仮定】 |

## 3. 環境と決まり（environment ルール）
| 項目 | 決まり |
|---|---|
| DB | どの試験も `:memory:`。ファイルの DB を使わない |
| E2E のサーバー | Playwright の `webServer` が 3000（`scripts/start-demo.ts`、DEMO_MODE=1）と 3100（`main.ts`、DEMO_MODE=0）を起動し、終わると止める。`reuseExistingServer: false` |
| 並列 | `workers: 1`・`fullyParallel: false`・`retries: 0` |
| 状態 | 試験ごとに新しいブラウザコンテキスト（localStorage は空）＝新しいダミー ID。サーバーの DB はダミー ID ごとに分かれるので、試験どうしの順序に依存しない |
| 外部 | 地理院タイルは 1×1 の PNG に差し替え、ほかの外部への要求は止めて記録し、0件であることを確かめる。CSP 違反のコンソール出力も0件 |
| VOICEVOX | 試験中はエンジンにつながない（何も listen していないポート 50999）。`/api/tts` は route で無音の WAV か 503 に差し替える。サーバー側は偽のエンジンで U を行う |
| 元 CSV | `C:\AI-Sprint\sample-data\` を読むだけ。T-037 で前後のハッシュを比べる |
| ポート | 実行の前後に `Get-NetTCPConnection -LocalPort 3000,3100,5173 -State Listen` で空いていることを確かめる。dev サーバー（5173）は止めておく |

## 4. 実行のコマンド
```powershell
Get-NetTCPConnection -LocalPort 3000,3100,5173 -State Listen -ErrorAction SilentlyContinue
npm run typecheck; npm run lint; npm test
npm run import:avatars
npm run test:e2e        # vite build → playwright test（全 E）
Get-NetTCPConnection -LocalPort 3000,3100,5173 -State Listen -ErrorAction SilentlyContinue
```
結果は実行の日時（`Get-Date`）・コマンド・件数を `試験結果.md` に書く。**実行していない試験の合否は書かない**（「未実行」と書く）。

## 5. 手で確かめる項目（M5）
| 項目 | 手順 | 関係 |
|---|---|---|
| キーボードの通し | マウスを使わず、E2Eデモシナリオの 1〜9 を Tab・Shift+Tab・Enter・Space・Esc だけで行う。フォーカスが常に見え、出典のプレート・下のメニューに隠れないこと | WCAG 2.1.1・2.4.7・2.4.11 |
| 200% 拡大 | Edge の拡大 200%・幅 390px で主要画面を開き、文字が切れず横スクロールが出ないこと | WCAG 1.4.4・1.4.10 |
| ナレーター | Windows のナレーターでホーム・すごろく・予言を読み、ボタン名・結果のお知らせ（`role=status`）が読まれること | WCAG 1.3.1・4.1.2・4.1.3 |
| 色覚 | Edge の DevTools の「視覚障害のエミュレート」（第1・第2・第3色覚）で季節の強調・クーポンの状態が色以外（文字・印）でも分かること | WCAG 1.4.1 |
| コントラスト | 主な文字と背景の組み合わせを相対輝度の式で計算する | WCAG 1.4.3・1.4.11 |
| 実際の VOICEVOX | 音声合成の準備.md の手順で ENGINE を起動し、4体の声で読み上げ・口の動き・クレジットを確かめる。止めてブラウザの声に戻ることも確かめる | AC-045・AC-050 |

結果は「実施した（日時・結果）」「実施できなかった（理由）」を分けて書く。

## 6. 始める条件・終わる条件
- 始める: そのユニットの typecheck・lint が通っている。
- ユニットの終わり: そのユニットの U と E が通る（ユニット計画 §3）。
- M4 の終わり: 全 U・全 E が1並列で通り、3000・3100・5173 が空いている。T-001〜T-066 のすべてに試験がある。
- M5 の終わり: 全試験をもう一度実行して記録し、§5 の手の確認を記録する。

## 7. 失敗したとき
`/fix` の手順（原因を説明してから直す）。**試験を消さない・緩めない・skip しない**。同じ試験が3回直らなければ止まって選んでもらう（autonomy ルール）。設計と違う試験だった場合は、設計書を根拠に試験を直し、audit に `AIの誤り` か `AI決定` を書く。

## 8. 【仮定】
- ブラウザは Edge だけ（Chromium 系。ほかのブラウザの追加ダウンロードをしない）。
- 実機のスマホの代わりに、390px（iPhone 14 など）と 430px（大きめのスマホ）の画面幅で確かめる。
- 自動のアクセシビリティ検査の道具（axe-core・pa11y）は許可ライセンス外のため使わず、§5 の手順と E の個別の確認で代える。
