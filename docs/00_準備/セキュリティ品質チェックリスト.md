## 2. 共通の確認コマンド（PowerShell 5.1 / Windows。バッククォートを含まない）
サーバーを 127.0.0.1:3000 で起動してから実行する。E2E の前は dev（5173）を止める。`curl.exe` は Windows 標準で、プロジェクトの依存ではない。
- **V1 ヘッダ全件**（HTML・API・静的・404 の4種で見る。`-D -` は全ステータスでヘッダを出す）:
  ```powershell
  foreach ($u in '/', '/api/health', '/assets/no-such.js', '/api/no-such') { "== $u"; curl.exe -sS -o NUL -D - "http://127.0.0.1:3000$u" }
  ```
- **V2 禁止パターン**（`/check` の B と同じ。0件で PASS）:
  ```powershell
  Get-ChildItem src,scripts,tests -Recurse -Include *.ts,*.tsx,*.css,*.html -ErrorAction SilentlyContinue | Select-String -Pattern 'innerHTML|outerHTML|insertAdjacentHTML|dangerouslySetInnerHTML|document\.write|\beval\(|new Function|child_process|node:vm'
  ```
- **V3 依存**: `npm audit`、`npm ls --all`、`npm ls typescript zod express better-sqlite3 --depth=0`
- **V4 型**: `npx tsc --noEmit`、`npx tsc --showConfig`（最終的な設定値を見る）
- **V5 外部通信**: Playwright の `page.on('request')` で、地理院タイル（`https://cyberjapandata.gsi.go.jp/xyz/pale/`）と `127.0.0.1` 以外の宛先が0件
- **V6 テスト一覧**: `npx vitest list`、`npx playwright test --list`（実行しなくても存在は確認できる。合否は実行して書く）

## 5. 適用外・逸脱の記録
適用しない、または資料と違う選択をしたものと、その理由。確認結果ではなく設計判断。変更したら ADR と audit に書く。

| 項目 | 資料の推奨 | 本件の扱い | 理由 |
|------|-----------|-----------|------|
| TLS・HSTS | EXP-SEC「Use TLS」、OWASP-HDR「Strict-Transport-Security」 | 使わない・送らない | 競技の制約が localhost のみ。HSTS なしはユーザー指定 |
| Helmet | EXP-SEC「Use Helmet」 | 使わない【仮定】 | 依存を増やさない。Helmet の既定は HSTS を付けるため、使う場合は無効化が必須。必要なヘッダは自前で付け、V1 で突合する |
| Referrer-Policy | OWASP-HDR は `strict-origin-when-cross-origin` を推奨 | `no-referrer`【仮定】 | 地理院へ参照元を送らない。表示に支障が無いことを SEC-HDR-03 で確認 |
| Strict CSP（nonce/hash） | OWASP-CSP「Strict CSP」 | 許可リスト方式の基本方針【仮定】 | 自前のバンドルのみでインラインが無く、OWASP も基本方針を代替として挙げる。SEC-CSP-07 |
| Cookie・セッション・CSRF トークン・ブルートフォース対策 | EXP-SEC、OWASP-NODE | 適用外 | ログインなし・Cookie なし。代わりに SEC-NODE-13 |
| COEP | OWASP-HDR「Cross-Origin-Embedder-Policy」 | 付けない【仮定】 | 外部の地理院タイルを遮断する恐れ。SEC-HDR-11 |
| ACL ライブラリ | OWASP-NODE「Use access control lists」 | 使わない | ロールが無い。SEC-NODE-16 |
| axe-core / @axe-core/playwright | （アクセシビリティの自動検査で一般的） | **導入しない** | ライセンスが MPL-2.0（許可は MIT/BSD/Apache/ISC のみ）。`npm view` で確認（2026-11-09）。pa11y も LGPL-3.0 で不可 |

## 6. 更新のルール
- 結果を書き換えるのは、実行・確認した直後だけ。`PASS`/`FAIL` には実行日時（`Get-Date`）、コマンド、対象を試験結果に書き、ここには ID を残す。
- 新しい項目は、出典と確認方法を付けて追加する。資料に無い判断は【仮定】。
- 到達点のゲート（`aidlc.mdc`）で、該当する時期の項目が `未確認` のまま残っていないか確認する。残すなら理由を state に書く。
