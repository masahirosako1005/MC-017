# アクセシビリティチェックリスト（WCAG 2.2 AA）

観光客がスマホで使う Web アプリのアクセシビリティ確認項目。セキュリティ・品質は [セキュリティ品質チェックリスト.md](セキュリティ品質チェックリスト.md)。

- **目標は WCAG 2.2 のレベル AA**。レベル A の 31 件と AA の 24 件、計 55 件を対象にする。AAA は目標外。
- **結果欄はすべて「未確認」**（作成: 2026-11-09 11:20）。画面もコードもまだ無い。実行・確認した項目だけ、日時と手順を添えて書き換える（`.cursor/rules/environment.mdc`）。
- 結果欄の値: `未確認` / `PASS` / `FAIL` / `対象外`（対象外は根拠を要件定義か画面設計に書く）。証跡は `docs/40_試験/試験結果.md`。
- **時期**: M3=画面設計・モックで決める / M4=実装と E2E / M5=最終確認。

### WCAG 2.2 の要点（WCAG22 の冒頭）
- WCAG 2.2 は 2.1 を拡張し、**4.1.1 構文解析は削除**された。本書の対象外。
- **2.2 の新しい達成基準**のうち A・AA は次の 6 件（表中は「2.2新規」）: 2.4.11 隠されないフォーカス（最低限）、2.5.7 ドラッグ動作、2.5.8 ターゲットのサイズ（最低限）、3.2.6 一貫したヘルプ、3.3.7 冗長な入力項目、3.3.8 アクセシブルな認証（最低限）。AAA の 2.4.12、2.4.13、3.3.9 は目標外。
- 達成基準の本文・例外は WCAG22 を正とする。本書の「確認方法」は、このアプリ向けの確認手順であり、基準の言い換えではない。

## 2. 共通の確認手順
自動検査ツールに頼らず、次の手順を組み合わせる。**`axe-core` と `@axe-core/playwright` は MPL-2.0、`pa11y` は LGPL-3.0 で、許可ライセンス（MIT/BSD/Apache/ISC）に合わないため入れない**（`npm view` で確認 2026-11-09）。

| 記号 | 手順 |
|------|------|
| K | キーボードのみ（Tab・Shift+Tab・Enter・Space・矢印・Esc）。Playwright では `page.keyboard` だけで操作する E2E |
| Z | 拡大: ブラウザの拡大 200%（手動）。リフローは Playwright の viewport を 320×640 にして確認 |
| O | 向き: viewport を 360×640 と 640×360 で確認 |
| R | ロール・名前: Playwright の `getByRole` / `getByLabel` で要素に到達でき、name が期待どおり。`locator.ariaSnapshot()` で構造を確認 |
| C | コントラスト: 色のデザイントークン（TypeScript の定数）から相対輝度で比率を計算する Vitest。依存は追加しない【仮定】 |
| B | 要素の寸法: Playwright の `boundingBox()` と `getComputedStyle`（`evaluate`） |
| V | 色覚: Chromium の色覚シミュレーション（CDP `Emulation.setEmulatedVisionDeficiency`）と、グレースケール表示で見比べる【仮定】 |
| N | スクリーンリーダー: Windows 標準のナレーターで主要シナリオを読み上げ（OS 標準で追加インストール無し）【仮定】 |
| L | 静的検査: `Select-String` による禁止パターン。`eslint-plugin-jsx-a11y`（MIT）の採否は M3 で決め、採るなら外部リソース.md に記録【仮定】 |
| S | テキスト間隔の上書きはインライン style を差し込むため、CSP（`style-src 'self'`）に遮られる。**この項目だけ** `bypassCSP: true` の別コンテキストで実行する【仮定】。CSP の試験は通常のコンテキストで行う |
