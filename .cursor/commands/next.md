# /next — 指定の到達点まで止まらず進める

使い方: `/next M2` `/next M3` … `/next M5`。引数なしなら `aidlc-state.md` の「次の到達点」。

## 手順
1. `AGENTS.md`、`.cursor/rules/`、`docs/00_準備/aidlc-state.md`、`docs/00_準備/audit.md` の末尾を読む。
2. 指定の到達点が「次の到達点」より先なら、間の到達点が完了済みか確認。未完なら先にそれを行う（飛ばさない）。
3. `docs/00_準備/AI-DLC軽量版.md` の「成果物一覧」から、その到達点の作る文書と順序を取り出す。
4. 文書を順に作る。**各文書は中身まで書く**（空・見出しだけ・TODO残しは不可）。事実には出典、資料にない仕様は【仮定】。
5. 1文書ごとに `aidlc-state.md` を更新（`[~]`→`[x]`）。ユーザーの指示・自分の誤り・決めた事は `audit.md` に**追記**（1行1件）。
6. 実装を伴う到達点（M4以降）は、ユニット単位。歩く骨組み(U-01) → 他ユニット。設計や独立ユニットはサブエージェントで並行してよい（共通ファイルは本体が直す。`parallel.mdc`）。ユニットごとに `/check` 相当を通して state を更新してから次へ。外部ライブラリは `npm view` → 外部リソース.md → `.npmrc` の `ignore-scripts=true` を確認 → install の順。設計上の決定は `docs/20_設計/adr/` に ADR を書く。
7. 到達点の最後に **ゲート**: R→US→SC→U→T の抜け・孤児、空ファイル、画面モック↔画面設計の1対1、audit の抜けを確認し、結果を state に書く。
8. 完了報告（3〜6行）: 作った物・ゲート結果・【仮定】の数・次の到達点。

## 止まる場合（これ以外は止まらない。詳細は `.cursor/rules/autonomy.mdc`）
1. 大会ルールに反する必要があるとき。
2. `npm install` が手順（`.npmrc`・`npm view`・`npm ls`・再実行）で直らないとき。
3. 同じテストが3回直らないとき（`/fix` で原因を説明して3回直しても失敗する）。
4. Must を削る必要があるとき。

止まるときは、起きたこと・試したこと・選択肢・推奨を示して `AskQuestion`。
**M2 だけは到達点が「補強案3つを出して人が選ぶ」**なので、案を出した所で終わる（選択は audit に `人の判断`）。選ばれるまで M3 に進まない。

それ以外の迷いは【仮定】で決めて audit に `AI決定` を1行足し、進む。**ユニットを終えるたびに `aidlc-state.md` を更新**し、時刻は `Get-Date` で実測する。

## 禁止
- 制約違反（外部通信・innerHTML・SQL連結・許可外ライセンス）を「後で直す」前提で入れる。
- テストを消す・緩める・skipする。
- 既存の audit 行の書き換え。
