# /fix — 原因を説明してから直す（テストは消さない）

使い方: `/fix`（直前の `/check` の FAIL）または `/fix <症状やテスト名>`。

## 手順（順番を守る）
1. **再現する**: 失敗するコマンドを実際に実行し、出力を確認する。再現しなければそう報告して止まる。
2. **原因を説明する（コードを直す前に、ユーザーに見える形で書く）**
   - 症状 → 直接の原因（ファイル・行・値）→ **根本原因**（なぜそうなったか）→ 影響範囲。
   - 推測は「推測」と書く。確認できた事実と分ける。
3. **最小の修正**をする。無関係な整理・リファクタを混ぜない。制約（competition / coding / ux ルール）を満たす形で。
4. **再発防止のテストを足す**（既に失敗していたテストが再発防止になっているなら、それを残す）。
5. **全体を再実行**（`/check` の A・B）。直した箇所だけでなく全テストが通ること。
6. `audit.md` に追記: AIが原因なら `AIの誤り`、方針を選んだなら `AI決定`、ユーザーが選んだなら `人の判断`（1行1件）。`aidlc-state.md` も更新。

## 絶対にしないこと
- テストの削除・コメントアウト・`skip`/`only`・期待値を実装に合わせて緩める・タイムアウトを伸ばして誤魔化す・スナップショットの無断更新。
- 制約の回避（テストを通すために外部通信・innerHTML・SQL連結を入れる）。
- 原因を説明せずに直す。

## テスト自体が間違っていると考えるとき
消さずに止まり、「どの期待値が、なぜ誤りか」を根拠付きで示して、ユーザーの判断を仰ぐ。承認されたら `人の判断` として audit に残して修正する。

## 3回直らない場合
**同じテストが3回直らない**と止まる条件（`autonomy.mdc`）。試した事・分かった事・選択肢（例: 仕様変更、スコープ縮小）・推奨を示して止まる。ただし選択肢が「Must を削る」「大会ルールに反する」なら、それ自体が止まる条件である旨を書く。
それ以外の判断は【仮定】で決め、audit に `AI決定` を足して進める。

## 実行の注意
- シェルは PowerShell。Git は使わない。時刻は `Get-Date`。
- E2E は dev を止めて 1 並列で実行し、毎回状態を戻す。DB は `:memory:`（`environment.mdc`）。
- 実行していないテストの合否は書かない。
